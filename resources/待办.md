## SKILL模块
**1. SKILL管理**
    - 架构层级：
        1. 来源分类：内置Skill / 用户自定义Skill
        2. 生命周期：注册 → 校验 → 版本管理 → 启用/禁用
        3. 元数据：名称、触发条件、依赖工具、权限要求
    - 调用思路：
        1. 用户请求或Agent上下文触发匹配
        2. 按触发条件（关键词/意图/显式@）检索候选Skill
        3. 权限与依赖校验通过后加载，失败则降级或提示
        4. 执行完成后回收，记录调用日志

**2. SKILL加载机制**
    - 架构层级：
        1. 懒加载：首次命中时加载，避免启动开销
        2. 预热加载：高频Skill常驻内存
        3. 隔离加载：每个Skill独立类加载器，互不污染
    - 调用思路：
        1. 注册表维护 name → loader 映射
        2. 命中后检查缓存，未命中则触发 loader
        3. 加载后注入上下文（工具、Prompt片段、权限声明）
        4. 加载失败回退到兜底策略

**3. SKILL调用机制**
    - 架构层级：
        1. 触发层：意图识别 / 显式调用 / 编排编排注入
        2. 执行层：工具链调用 / 子流程执行
        3. 结果层：结构化返回 / 副作用落地
    - 调用思路：
        1. Agent在推理循环中判断是否需要Skill
        2. 选定Skill后按定义编排其内部步骤
        3. 执行过程受执行臂权限硬边界约束
        4. 结果回传主链路，参与后续推理

## MCP模块
**1. MCP管理**
    - 架构层级：
        1. 来源分类：本地STDIO MCP / 远程SSE MCP / 云端MCP
        2. 连接状态：已连接 / 断开 / 重连中
        3. 能力目录：tools / resources / prompts 三类暴露面
    - 调用思路：
        1. 启动时按配置建立连接并拉取能力清单
        2. 能力清单注册进全局工具/资源目录
        3. 断线自动重连，重连后重新同步清单
        4. 配置变更触发热重载

**2. MCP执行链路**
    - 架构层级：
        1. 协议层：JSON-RPC 请求/响应/通知
        2. 适配层：MCP tool ↔ 框架Tool契约转换
        3. 鉴权层：传输级令牌 / 调用级权限
    - 调用思路：
        1. Agent将MCP工具视作普通工具调用
        2. 适配层把框架Tool调用翻译为MCP协议请求
        3. 结果经适配层还原为ToolResult回传
        4. 错误以isError返回，不向上抛异常

**3. MCP嵌入策略**
    - 架构层级：
        1. 全局嵌入：所有Agent默认可用
        2. 场景嵌入：特定Agent/子任务专属
        3. 按需嵌入：会话中动态挂载/卸载
    - 调用思路：
        1. 编排阶段声明本Agent可见的MCP集合
        2. 运行时按权限与上下文动态裁剪可见工具
        3. 子代理继承父级MCP权限，不提升边界

## 记忆模块（先归纳，再清洗）
**1. 记忆管理**
    - 架构层级：
        1. 分类引入
            - 时间维度：长期记忆（按项目管理）/ 会话记忆 / 代理记忆
            - 类型维度：用户记忆 / 组织记忆 / 本地记忆
        2. 数据清洗：去噪、去重、归一化、敏感信息脱敏
        3. 记忆压缩：摘要化、指纹去冗余、分级保留
    - 调用思路：
        1. 写入时先按时间+类型双维度归类
        2. 落地前经清洗流水线（脱敏→去重→归一）
        3. 定期压缩，控制单项目记忆体积上限

**2. 记忆调用链路**
    - 架构层级：
        1. 会话记忆
            - 定期清理：TTL过期、低频淘汰
            - 边执行边存储/定量存储/会话上下文达阈值90%后压缩存储
        2. 长期记忆写入
            - 会话记忆自动沉淀到长期记忆
            - 用户显式指定写入长期记忆
            - 代理任务结束后归档
    - 调用思路：
        1. 推理前先拉取会话记忆作为即时上下文
        2. 需要时按项目检索长期记忆做补充
        3. 写入按"会话→长期"二级回流，保证可追溯

**3. 记忆加载机制**
    - 架构层级：
        1. 调用优先级：会话记忆 > 长期记忆（指定项目搜索）
        2. 冲突处理：优先LLM提示，再按会话记忆执行
        3. 加载范围：当前项目上下文优先，跨项目按需
    - 调用思路：
        1. 会话开始加载会话记忆预热上下文
        2. 遇到知识盲区按项目检索长期记忆
        3. 记忆冲突时以LLM判断+会话记忆为最终依据

## 执行模块
**1. 执行模式**
    - 架构层级：
        1. 交互模式：单轮问答 / 多轮会话 / 自主任务
        2. 并行模式：串行 / 并行（受在途数约束，默认8）
        3. 干预模式：全自动 / 人工确认（ASK）/ 只读预览
    - 调用思路：
        1. 按任务类型选择交互与并行模式
        2. 危险操作强制ASK挂起，持久化待恢复
        3. 进程重启后从pending-ask恢复挂起态

**2. 框架设计**
    - 架构层级：
        1. 编排中枢：agent-core 统一编排，不另起推理循环
        2. 执行臂：权限硬边界 + realpath路径锚定
        3. 事件流：ConversationStateManager + Flux<AgentEvent>
    - 调用思路：
        1. 内核与通道解耦，Web/CLI共用同一事件流
        2. 每次循环边界检查maxTurns/maxBudget
        3. 所有文件/命令操作必经执行臂校验

**3. Agent编排**
    - 架构层级：
        1. 主Agent：任务分解、调度、聚合
        2. 子Agent：按SubAgentSpec创建，共享权限边界
        3. 编排策略：串行 / 并行 / 条件分支
    - 调用思路：
        1. 主Agent拆分任务为子任务列表
        2. 按SubAgentSpec下发工具/权限/上限
        3. 聚合子代理摘要，回写主链路上下文

**4. 主子Agent调用**
    - 架构层级：
        1. 创建：SubAgentSpec(tools/disallowedTools/maxTurns/maxTokens/permissionMode/summaryOnly/isolation)
        2. 隔离：共享REACT引擎、权限级别、执行臂硬边界
        3. 返回：仅摘要或结构化结果，不提升权限
    - 调用思路：
        1. 默认单Agent，多Agent按需启用
        2. 子代理执行受父级权限约束，越权操作被拒
        3. 界面展示子任务进度与状态

**5. React框架设计**
    - 架构层级：
        1. 推理层：观察→思考→行动→观察循环
        2. 工具层：Tool契约(ToolAnnotations: readOnly/destructive/idempotent)
        3. 调度层：只读工具并行、写工具串行
    - 调用思路：
        1. 每轮观察环境，LLM决策下一步action
        2. 工具结果以ToolResult返回，错误走isError
        3. 循环至达到目标或命中终止条件

**6. 多Agent协作**
    - 架构层级：
        1. 角色分配：规划者/执行者/评审者
        2. 通信总线：共享上下文 + 事件流
        3. 冲突裁决：主Agent最终聚合权
    - 调用思路：
        1. 规划者分解，执行者并发，评审者校验
        2. 通过共享上下文传递中间产物
        3. 主Agent汇总并消解分歧

**7. 上下文压缩策略**
    - 架构层级：
        1. 五级CompactionPipeline接口
        2. MVP实现：工具结果裁剪 + 基础摘要
        3. 后续：PreCompact/PostCompact Hook、preservedSegment、失败熔断
    - 调用思路：
        1. 会话达阈值（90%）触发压缩
        2. 按优先级保留preservedSegment
        3. 压缩失败触发熔断，保留原始上下文

**8. 历史记录调用策略**
    - 架构层级：
        1. 会话级：当前会话滚动窗口
        2. 项目级：跨会话长期归档检索
        3. 全局级：用户偏好/通用知识
    - 调用思路：
        1. 近端历史直接注入，远端历史按需检索
        2. 结合记忆模块做关联召回
        3. 控制注入体积，避免超出预算

**9. 任务拆分**
    - 架构层级：
        1. 粒度：大任务→小任务列表（可独立执行）
        2. 依赖：有向无环图表达前后置
        3. 分配：按工具/权限亲和度分配到Agent
    - 调用思路：
        1. LLM生成任务树，编排层校验可行性
        2. 按依赖关系排程执行顺序
        3. 完成态上报，触发下游任务

**10. 思考深度选择**
    - 架构层级：
        1. 轻量：快速响应，跳过深度推理
        2. 标准：常规ReAct循环
        3. 深度：多步规划+自反思+校验
    - 调用思路：
        1. 按任务复杂度自动/手动选档
        2. 深度档增加反思与评审环节
        3. 预算随深度档位放大

**11. 对话全链路观测**
    - 架构层级：
        1. 事件层：AgentEvent全量埋点
        2. 生命周期：AgentLifecycleEvent + 有序监听器链（deny-wins）
        3. 观测层：Trace/日志/指标
    - 调用思路：
        1. 关键节点发射生命周期事件
        2. 监听器链按序处理，deny优先
        3. 全链路可追溯，支持回放与审计

## 工作流模块
**1. 组件设计**
    - 架构层级：
        1. 原子组件：LLM节点 / 工具节点 / 条件节点 / 代码节点
        2. 组合组件：子流程 / 循环 / 分支
        3. 连接器：输入映射 / 输出映射
    - 调用思路：
        1. 组件声明IO契约与副作用类型
        2. 编排时校验组件兼容性
        3. 运行时按拓扑顺序实例化

**2. 组件管理**
    - 架构层级：
        1. 注册：组件目录 + 版本
        2. 权限：组件级执行权限声明
        3. 复用：跨工作流共享组件库
    - 调用思路：
        1. 组件注册进全局目录供编排引用
        2. 权限继承工作流所属Agent边界
        3. 版本升级触发引用方兼容性检查

**3. 工作流编排**
    - 架构层级：
        1. 拓扑层：DAG定义节点与边
        2. 调度层：串行/并行/条件触发
        3. 数据层：上下文变量作用域
    - 调用思路：
        1. 用户/编排器构建DAG
        2. 按边条件驱动流转
        3. 变量作用域隔离，避免污染

**4. 编排和执行链路**
    - 架构层级：
        1. 编译：DAG → 可执行计划
        2. 执行：节点逐个经执行臂校验
        3. 聚合：结果回流主上下文
    - 调用思路：
        1. 编译期做静态校验（权限/变量/死锁）
        2. 执行期每节点复用React执行臂
        3. 失败节点按策略重试/跳过/终止

**5. 沙箱环境**
    - 架构层级：
        1. 进程沙箱：受限执行环境
        2. 资源沙箱：CPU/内存/时间配额
        3. 文件系统沙箱：realpath边界
    - 调用思路：
        1. 代码/工具节点默认进沙箱
        2. 越界操作被执行臂实时阻断
        3. 沙箱配额超限触发熔断

**6. 功能点与实现点分析（基于现有代码盘点）**
    - 功能点（用户可见能力）：
        1. DAG 可视化编排：前端画布拖拽节点/连线（新增 `web/fronted` 路由 + Vue Flow）
        2. 原子组件：LLM / 工具 / 条件 / 代码 四类节点
        3. 组合组件：子流程 / 循环 / 分支
        4. 组件库：注册 + 版本 + 跨工作流复用
        5. 编译与确定性执行：DAG → 可执行计划，按边条件流转
        6. 执行臂校验 + 沙箱 + 运行监控（SSE 进度）
    - 实现点（对应现有代码，避免重复造轮子）：
        - DAG 引擎：`agent-core/service/LangGraphOrchestrator` 已用 `org.bsc.langgraph4j.StateGraph` 跑通图编排 → 工作流编译器直接复用，不另行实现 DAG
        - LLM 节点：`agent-core/util/engine/ReactEngine` + `Orchestrator` 的 analyze 节点
        - 工具节点：`agent-core/util/gateway/ToolGateway`（注册/分发）+ `agent-executor/support/gateway/FileOpsToolset`
        - 条件/分支节点：LangGraph4j 的 conditional edges
        - 代码节点：`agent-executor/support/arm/CmdSandbox.run()`（ProcessBuilder + 超时，默认关闭需授权）
        - 子流程/并行/聚合：`agent-core/util/subagent/` 下 `SubAgentExecutor`、`SubAgentFactory`、`TaskScheduler`、`ResultAggregator`
        - 组件隔离/权限声明：复用 `agent-common/contract/SubAgentSpec`（tools / permissionMode / isolation …）
        - 编译期静态校验（环检测/权限/变量）：参考 `agent-core/models` 的 `PlanValidator` / `PlanSchema`
        - 执行臂硬边界：`agent-executor/support/arm/BoundaryGuard.realpathWithin()`（realpath 越界阻断）
        - 权限规则链：`agent-executor` 的 `PermissionRuleCache` + deny>ask>allow
        - 进度事件：`agent-core/util/runtime/` 的 `ConversationStateManager` + `Flux<AgentEvent>` + `AgentEventPublisher`
        - 落盘：`agent-workspace` 的 `WorkspaceConfig.physicalPathOf()`，工作流定义存用户工作空间（不进 MySQL，符合 D4/D5）
    - 新增范围（必须新建的部分）：
        1. `web/app` 下新建 Maven 模块 `agent-workflow`（依赖 agent-core / agent-executor / agent-common / agent-workspace / agent-permission）
        2. 领域模型：`WorkflowDef` / `NodeDef` / `EdgeDef` / `ComponentLibrary`
        3. `WorkflowCompiler`（DAG → StateGraph + 环检测等静态校验）、`WorkflowRuntime`（节点分发执行）
        4. 前端 `/workflow` 路由：Vue Flow 画布 + 节点属性面板 + SSE 运行监控
    - 关键约束：
        1. 工作流是确定性调度，LLM 节点应为单步确定性调用；组合组件「子流程」才挂 `SubAgentSpec`（避免与 ReAct 自主推理混淆）
        2. 编译器必须做 DAG 无环校验 + 单轮预算上限，防止 StateGraph 死循环（已有长任务递归失控风险）
        3. 节点间数据用工作流级私有作用域，聚合后才回流主会话
        4. 代码节点强依赖 `CmdSandbox`，需先把沙箱开关/配额产品化（设置页）

    - 架构层级：

        3. 缓存分界：静态/动态五级覆盖优先级
    - 调用思路：

        2. 动态段每轮按上下文重新组装

**3. Prompt管理**

    - 调用思路：

## LLM配置
**1. 支持调用方式**
    - 架构层级：
        1. API Key调用：云端模型，Key加密落盘（AES-GCM + PBKDF2/OS密钥链）
        2. 本地LLM部署：本机推理服务，不依赖公网
        3. 路由：按模型供应商能力选择
    - 调用思路：
        1. Key第一阶段即加密，禁止明文写盘
        2. 本地模型走本地端点，零外传
        3. 调用前检查Key可用性

**2. LLM管理**
    - 架构层级：
        1. 模型注册：名称/供应商/端点/能力
        2. 在途控制：模型在途数默认8
        3. 角色分配：主模型/兜底模型/轻量模型
    - 调用思路：
        1. 任务按复杂度选模型档位
        2. 主模型失败回落兜底模型
        3. 在途数超限排队，避免过载

**3. LLM用量表**
    - 架构层级：
        1. 计量维度：token/调用次数/时长
        2. 统计粒度：按会话/项目/模型
        3. 本地优先：用量只在本机记录，不回传
    - 调用思路：
        1. 每次调用后累计用量指标
        2. 超预算触发告警或降级
        3. 数据落本机，符合零托管原则
