# Phase 1 实现文档：MVP 基础框架闭环（架构锁定）

> 关联需求：§2.1 多模块结构、§2.2 单机抗并发、§3.0 工作空间目录规范、§4.1–4.5 编排/记忆/权限/执行臂、§4.8 工作区管理、§4.9 文件操作、§4.10–4.12 权限与越界、§4.14 大模型本地配置直连、§5.1 本机账号。
> 风险闭环：R1/R2/R4/R7/R8/R9/R10。

## 1. 阶段目标
搭建可运行的 Agent 框架 MVP，并在本阶段锁定底层架构：JDK 17+ / Spring Boot 3.x / Maven / LangChain4j + LangGraph4j（核心）+ Spring AI（辅助）；通过 `ExecutionTransport` 本机模式（进程内/IPC）连接执行臂；交付本地部署包与一键启动脚本（`lucky start` / `start.bat` / `start.sh`）；实现 `ConversationStateManager` + `Flux<AgentEvent>` + WebChannel；落地 `resources/file/契约定义.md`；内部 Hook 事件契约；`deny > ask > allow` 基础权限规则链与执行臂本地重新评估；子代理基础执行（任务分解、串行子代理、摘要返回、独立预算、结果聚合）；复杂任务拆分与对话界面任务列表/进度展示；ToolAnnotations；CompactionPipeline 接口与最小实现；提示词静态/动态分界；记忆双轨、模型本地配置直连（Key 加密）、Web 文件操作。落实 §3.0 目录规范与 `.tmp/` 锁文件契约。

### 1.1 架构锁定项（必须）

- 技术栈：JDK 17+、Spring Boot 3.x、Maven 多模块、LangChain4j + LangGraph4j（核心）+ Spring AI（辅助）。
- 传输：`ExecutionTransport` 抽象固定，Phase 1 使用本机进程内/IPC，不引入 WSS。
- 控制流：`ConversationStateManager` 是会话状态唯一事实源，引擎输出 `Flux<AgentEvent>`，WebChannel 只消费事件流。
- 事件契约：`AgentEvent` 类型与 Hook 事件名固定（SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / PreCompact / PostCompact / SubagentStart / SubagentStop / Stop）。
- 权限：`deny > ask > allow` 规则链 + `PermissionDecision` + realpath 硬边界；MVP 实现基础路径规则。
- 执行臂信任：权限规则同步到执行臂本地，执行臂每次操作重新评估，框架侧裁决仅作提示。
- 子代理：`SubAgentSpec` 契约固定（tools / disallowedTools / maxTurns / maxTokens / permissionMode / summaryOnly / isolation），MVP 只回摘要或结构化结果。
- 工具：`Tool` 含 `ToolAnnotations`，只读工具并行、写工具串行，错误以 `ToolResult.isError` 返回。
- 压缩：五级 `CompactionPipeline` 接口固定，MVP 实现工具结果裁剪和基础摘要。
- 提示词：静态/动态分界 + 五级覆盖优先级固定，`cache_control` 后续接入。
- 通道：`AgentChannel` 契约固定，MVP 只实现 WebChannel。
- 契约：`resources/file/契约定义.md` 为 AgentEvent、HookEvent、PermissionRule、SubAgentSpec、AgentChannel、ExecutionTransport 的唯一事实源。

├── agent-permission  api: PermissionService; impl: 级别配置

├── agent-persona     api: PersonaService; impl: 预设/自定义

## 4. 工作空间目录落地（§3.0）
首次启动按 §3.0 建目录：frameworkRoot（默认 `%LOCALAPPDATA%/lucky_agent`）+ workspaceRoot（默认 `C:/lucky_agent` 或用户指定）：
```
<frameworkRoot>/         框架隐藏目录
 ├─ .config/            配置/权限级别/模型Key+URL（加密）/账号
 ├─ .memory/            用户记忆 JSONL + 向量索引
 ├─ .platform/          平台预置记忆（随包，只读）
 ├─ .rollback/          快照（按 workspaceId 分桶，Phase2 用）
 ├─ .cache/             预留（Phase2）
 ├─ .logs/              审计/模型trace（仅元数据）
 ├─ .skills/ .mcp/      预留（Phase3）
 ├─ .tmp/               锁文件+临时中转（见 §6 锁契约）
 ├─ .trash/             回收站（按 workspaceId 分桶）
 └─ .agent/             执行臂程序与运行态（见 §7）
<workspaceRoot>/         用户指定路径，只放用户产物
 └─ <workspace>/        用户产物，按 workspaceId 隔离
```
目录创建失败（如根盘满）按 §4.9 捕获 IO 异常，提示"工作空间所在磁盘已满，无法执行文件操作"。

## 5. 核心编排：统一 REACT 引擎（§4.4/§4.5）
- 单 `ReactEngine` 服务于 PLAN/ACT/ASK，仅系统提示/目标/终止条件不同。
- `ConversationStateManager` 维护会话状态唯一事实源；引擎以 `Flux<AgentEvent>` 输出，WebChannel 消费同一事件流。
- `Plan` 对象 schema 契约 + `PlanValidator`：非法计划拒绝并重规划。
- 步数上限（如 PLAN 12 步、ACT 每步 8 步）+ 早停：超步数转 ASK/重规划。
- 每轮 Thought/Action/Observation 写入本机记忆与 `.logs/` trace（仅元数据）。
- 子代理基础执行：主 Agent 可在 PLAN 中识别可独立执行的子任务，串行创建子代理执行并聚合结果；多 Agent 并行编排增强在 Phase3。
- 复杂任务拆分与进度展示：主 Agent 将复杂任务拆成小任务列表，core 推送 `task_plan`/`task_progress` 事件，Web 对话界面展示清单、当前步骤与完成比例。

### 5.1 对话调用链路
```
Web(HTTPS/SSE) → agent-web WebChannel
  → agent-core ReactEngine(PLAN→ACT→ASK)
      ├─ 调 agent-model（本地配置直连 LLM）
      ├─ 调 agent-memory（召回用户/平台双轨，打标注入）
      ├─ 调 agent-executor（文件操作经本机执行臂）
      └─ 调 agent-workspace/permission（取权限级别带入上下文）
  → Flux<AgentEvent> 经 SSE 流式回前端
```

## 6. 并发控制与锁契约（§2.2 / R10）
`agent-common.FileLockGuard` 实现 §3.0 锁契约：
- **锁文件**：`<frameworkRoot>/.tmp/<workspaceId>.<relPath>.lock`，首行 `PID|timestamp|leaseMs(默认30000)`。
- **获取**：建锁前原子写 `.lock.tmp`→`rename`；已存在则读首行，PID 不存在或超时→删后抢占；否则等待（总上限防止死等）。
- **释放**：`try-finally` 删除；注册 `Runtime.addShutdownHook` 清理本进程锁。
- **启动清理**：进程启动扫描 `.tmp/`，删 PID 已死/超时 stale 锁与残留 `.part`。
- **信号量/令牌桶**：模型调用在途数用 `Semaphore` 限流（默认 8）；全局入口 `Guava RateLimiter`；单用户对话串行队列 + 全局公平池。

## 7. 本机执行臂与越界防护（§4.11/§4.12）
- Phase 1 执行臂与内核同进程或本机 IPC，通过 `ExecutionTransport` 通信，不引入 WSS；方案 B 时再切换 WSS 加密长连接 + 双向鉴权。
- **硬边界**：每次文件/命令操作 `realpath` 规范化，阻断 `../`、符号链接逃逸出工作空间——**执行臂是权限与越界的最终裁决者**，无论 LLM/框架如何决策，执行臂不越界。
- 权限级别（只读/修改/全部）由 Phase 调用带入上下文；权限规则同步到执行臂本地，执行臂重新评估 `deny > ask > allow`，**执行臂为最终裁决者**，本地校验为唯一生效源。
- 命令执行沙箱默认关闭，开启需用户显式授权；进程完整性签名校验防替换。

## 8. 大模型本地配置直连（§4.14）
- 用户在本机 `<frameworkRoot>/.config/` 配 `endpointUrl + apiKey + modelName`，Key/URL 以 PBKDF2/OS 密钥链派生密钥 + AES-GCM 加密落盘，明文不写盘。
- `agent-model` 仅读取本机配置调用 LLM，不向平台上报 Key/URL、不引入平台唯一 ID、不做激活配对/token 校验。
- 路由：单模型退化为直通；预留多模型路由（Phase3 增强）。fallback 切备用端点。

## 9. 工作区与权限管理（§4.8/§4.10）
- 用户"添加工作空间"填本机目录 → 生成 `workspaceId` 绑定用户与本机路径，存 `<frameworkRoot>/.config/`。
- 权限级别三选一：只读 / 修改文件 / 全部权限（含执行），随工作区配置存 `<frameworkRoot>/.config/`。
- 每次对话调用把该工作区权限级别作为上下文带入，`deny > ask > allow` 规则链裁决；高危（删/执行/覆盖）对话中 ASK 确认。

## 10. 记忆双轨（§3.1–3.5 / R4/R7）
- 用户层面：绑定本机用户，运行时内存 + 必选本机 `<frameworkRoot>/.memory/` JSONL+向量索引持久化；跨会话恢复。
- 平台层面：随包内置 `<frameworkRoot>/.platform/`，运行时加载进内存参与推理，用户只读。
- **隐私防火墙**：用户记忆只写本机文件，无上行通道；平台记忆走发行包更新，物理隔断上漂（R4 闭环）。
- 启动时从 `<frameworkRoot>/.memory/` 与 `<frameworkRoot>/.platform/` 加载；进程退出/重启自动恢复（R7 闭环）。

## 11. 技术需求方案与思路架构分析

> 本章对 Phase 1 涉及的技术需求逐条展开「为什么这么做 / 关键方案选型 / 架构权衡」，供实现前对齐思路。

### 11.1 多模块 Maven 单体工程（§2.1）
**需求**：按业务域拆 module，接口契约解耦，预留微服务拆分。
**方案与思路**：
- 采用 `parent(pom) + N 个 submodule` 结构；每个 module 内部再分 `api`（接口+DTO，对外契约）与 `impl`（实现，不跨模块暴露）。
- **解耦关键**：跨模块只允许依赖 `api` 包；Spring 注入接口而非实现；循环依赖用**领域事件 / 回调**打破（如记忆写完成事件、文件操作完成事件）。
- **微服务预留**：在 `api` 接口上打 `@Remote(serviceName)` 注解，值为未来 RPC 服务名。该注解本阶段是"无操作标记"，演进阶段才被 RPC 框架识别——保证演进时**业务代码零改**。
- **权衡**：单体优先而非起步微服务，因用户数据全在本机、零托管，单机并发靠模块内线程池即可；过早微服务反而引入分布式复杂度且无收益。

### 11.2 单机抗并发（§2.2 / R10）
**需求**：不引入 Redis/Sentinel 前提下扛多用户并发对话与模型调用。
**方案与思路**：
- **模型在途数**：`Semaphore`（默认 8）限制同时打向模型的请求，防线程耗尽（R6）。
- **对话排队**：单用户串行队列（防同用户对话交错）+ 全局公平线程池（防单用户占满）。
- **记忆/文件并发写**：`ReadWriteLock` + 文件版本号防冲突；锁契约见 11.6。
- **长任务不阻塞**：Project Reactor `Flux<AgentEvent>` + SSE 推送，内核线程不被长推理占死。
- **限流**：本地 `Guava RateLimiter` 令牌桶，预留 Sentinel 替换点（统一抽象在 `agent-common`）。
- **架构核心**：所有并发手段封装为 `agent-common` 的 `ConcurrencyGuard`/`RateLimiter` 抽象，未来换 Redis/Sentinel 实现不动业务代码。

### 11.3 工作空间目录规范（§3.0）
**需求**：全模块统一落盘约定，禁止工作空间外写用户数据。
**方案与思路**：
- 集中定义 `<frameworkRoot>/` 下 `.config/.memory/.platform/.rollback/.cache/.logs/.skills/.mcp/.tmp/.trash/.agent` 等隐藏目录职责与归属模块（见 §4）。
- `agent-common.WorkspaceDirs` 常量统一引用，任何模块写盘必须从该常量取路径——从**编译期**杜绝私自外写。
- 首次启动按 §3.0 创建；根盘满按 §4.9 捕获 `IOException` 提示，不崩。

### 11.4 统一 REACT 引擎 + PLAN-ACT-ASK（§4.4/§4.5）
**需求**：三层执行模式统一底层，避免双层嵌套循环失控；非法计划不执行。
**方案与思路**：
- **核心论点**：PLAN/ACT/ASK 不是三个独立循环，而是**同一个 `ReactEngine` 的三种运行模式**，仅 System Prompt / 目标 / 终止条件不同。这是防"双层循环失控"的根本设计。
- **计划校验**：`Plan` 对象绑定 JSON Schema 契约 + `PlanValidator`；PLAN 产出非法（缺字段/无法解析/含越权步骤）则拒绝并 `Replanner` 重规划（闭环 R3）。
- **步数上限 + 早停**：PLAN 12 步、ACT 每步 8 步；超限强制转 ASK / 重规划，防无限试错降本。
- **追溯**：每轮 Thought/Action/Observation 落本机记忆 + `.logs/` trace（仅元数据）。

### 11.5 记忆双轨 + 本机持久化（§3.1–3.5 / R4/R7）
**需求**：用户/平台两轨隔离；记忆不丢（必选落盘）；用户记忆不上漂平台（隐私红线）。
**方案与思路**：
- **双轨管线**：噪声过滤 → 清洗 → 分层（按归属拆用户/平台）→ 事实萃取（置信度/冲突/去重）→ 沉淀。横切检索 + 遗忘/衰减作用于两轨。
- **持久化**：运行态在内存（低延迟），跨会话必选落盘 `<frameworkRoot>/.memory/`（JSONL + 本地向量索引）；重启自动加载（闭环 R7）。
- **隐私防火墙（机制而非声明）**：用户记忆**只写本机文件、无上行通道**；平台记忆随发行包更新（`<frameworkRoot>/.platform/` 只读）。架构上物理隔断用户记忆上漂平台（闭环 R4）。
- **本地向量**：不引云端向量库，用本机轻量向量索引（HNSW/余弦），文件 `mem.jsonl` + `index.bin` 可重建。

### 11.6 并发锁契约与防死锁（§3.0 / R10）
**需求**：并发读写锁文件残留不致死锁。
**方案与思路**（`.tmp/` 锁契约落地）：
- **命名/格式**：`<workspaceId>.<relPath>.lock`，首行 `PID|timestamp|leaseMs(30000)`；原子写 `.lock.tmp`→`rename` 防半写。
- **获取**：已存在则读首行，PID 死或超时 → stale 锁直接抢占覆盖；否则等待重试（带总上限防无限阻塞）。
- **释放**：`try-finally` 删锁 + `Runtime.addShutdownHook` 兜底清理本进程锁。
- **启动清理**：扫描 `.tmp/`，删 PID 已死/超时 stale 锁与残留 `.part`。
- **架构意义**：把"锁残留死锁"这一框架自身机制缺陷，转化为确定性的 stale 抢占 + 启动清理协议，R10 闭环。

### 11.7 本机执行臂与越界防护（§4.11/§4.12 / R1/R2）
**需求**：Web 无法直接操本机文件，必须有本机桥接；执行臂被劫持不能越权/泄露。
**方案与思路**：
- **必备组件**：执行臂是唯一执行侧。Phase 1 与内核同进程或本机 IPC（`ExecutionTransport`）；方案 B 时改为 WSS 加密长连接 + 双向鉴权。
- **硬边界（核心）**：每次文件/命令在操作前由执行臂本地做 `realpath` 规范化，阻断 `../`、符号链接逃逸出工作空间——**无论 LLM/框架服务端如何决策，执行臂不越界**（闭环 R1/R2 的"越界"面）。**执行臂为最终裁决者**：权限规则链结果作为决策输入，越界防护与可执行范围以执行臂本地校验为准（与 §4.10 一致）。
- **权限级别**：只读/修改/全部由调用上下文带入；精确权限由 `deny > ask > allow` 规则链裁决，**执行臂是最终裁决者**，硬边界与权限以执行臂本地校验为唯一生效源（与 §4.10 一致）。
- **防劫持**：进程完整性签名校验（被替换拒绝启动）；命令执行沙箱默认关，开启需用户显式授权。

### 11.8 模型本地配置直连（§4.14）
**需求**：框架只编排不收费；不引入平台 ID / 激活配对。
**方案与思路**：
- 用户本机 `<frameworkRoot>/.config/` 配 `endpointUrl+apiKey+modelName`，Key/URL 加密落盘（PBKDF2/OS 密钥链 + AES-GCM）；`agent-model` 仅读配置调用 LLM。
- 不向平台上报 Key/URL、不引入平台唯一 ID、不做 token 校验/激活配对。
- 路由：单模型退化为直通；预留多模型路由（Phase3 增强）；fallback 切备用端点。

### 11.9 工作区与权限管理（§4.8/§4.10）
**需求**：轻量工作区；权限级别配置带入对话，规则链执行 `deny > ask > allow` 基础裁决，执行臂为最终裁决者。
**方案与思路**：
- 用户"添加工作空间"填本机目录 → 生成 `workspaceId` 绑定用户+路径，存 `<frameworkRoot>/.config/`（零托管）。
- 权限三选一（只读/修改/全部）随工作区存 `<frameworkRoot>/.config/`；每次调用带入上下文，`deny > ask > allow` 规则链裁决，**执行臂为最终裁决者**。
- 高危（删/执行/覆盖）对话中 ASK 确认——规则链 `ask` 与用户确认结合，执行臂硬边界兜底。

### 11.10 本机账号（§5.1）
**需求**：无中心化用户库，本机本地身份隔离多用户。
**方案与思路**：账号为本机本地身份（存 `<frameworkRoot>/.config/`），仅用于本机多用户配置/记忆隔离；登录/会话本机完成，无注册、无中心库。

### 11.11 本地部署与快速启动（OpenClaw 式）

**需求**：用户下载服务包后，通过一键命令/脚本在本地启动，浏览器访问本地 Web 使用 Agent，不依赖云服务器。
**方案与思路**：
- 发布 `lucky-agent-<version>.zip`，包含后端 jar、前端构建产物、执行臂、`lucky`/`start.bat`/`start.sh` 脚本与默认配置。
- `lucky start` 首次运行自动初始化 `frameworkRoot`/`workspaceRoot`，启动后端并托管前端静态资源，默认监听 `127.0.0.1:8080` 并打开浏览器。
- `lucky stop` 停止服务但不删除用户数据；再次启动自动恢复会话与记忆。
- 默认仅本机访问，局域网访问需显式配置。
- 方案 B（云端服务端 + 本机执行臂）仍为后续演进项，不改变当前本地部署形态。
