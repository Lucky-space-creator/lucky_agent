# Phase 3 实现文档：扩展能力

> 关联需求：§4.2 Skill 管理、§4.3 MCP 扩展、§4.14 多模型路由增强、§6.3 工具按需召回 Top-K、前端 token/调用透明化；八项差距 D13 外部 Hook、D15 worktree 隔离。
> 风险闭环：Skill/MCP 加载与权限边界（执行臂越界防护已覆盖）。

## 1. 阶段目标
在主链路与体验层之上扩展：Skill/MCP 高级增强（版本管理、隔离加载、Tool Search、热重载）、多模型路由增强、多 Agent 并行编排增强（fan-out/fan-in）、JGit worktree 隔离、外部 Hook（Shell/Webhook/MCP Tool）、工具按需召回 Top-K、前端 token/调用透明化。

## 2. 涉及模块与交付物
| 模块 | 交付内容 |
|---|---|
| agent-skill | Skill 版本管理、隔离类加载、预热加载、依赖解析、高级语义匹配 |
| agent-mcp | MCP Tool Search 按需加载、断线重连、配置热重载、场景嵌入、授权隔离增强 |
| agent-model | 多模型路由策略（小模型辅助/主模型推理） |
| agent-core | 工具注册表注入 Skill/MCP 为 LangChain4j Tool；Top-K 召回；多 Agent 并行调度（TaskScheduler fan-out/fan-in）；外部 Hook 适配 |
| agent-executor | JGit worktree 隔离（副作用密集子代理） |
| agent-web | token/调用数/缓存命中透明面板 |

## 3. Skill 高级管理（§4.2）
- **注册**：平台预装常用 Skill（随包 `.platform/`）；用户开关/安装到 `.skills/`。
- **映射**：每个 Skill 映射为 LangChain4j Tool/子 Agent。
- **语义匹配 Top-K**：运行时按任务语义召回 Top-K（非全量）注入上下文，省 token（§6.3）。
- **热插拔**：支持运行时加载/卸载，不重启内核。
- **执行沙箱**：Skill 执行默认关沙箱（命令执行同 §4.11 默认关）；开启需用户显式授权。
- **安全边界**：Skill 脚本执行仍经本机执行臂 `realpath` 越界防护（§4.11/§4.12），不逃逸工作空间。

### 3.1 Skill 元数据（伪）
```
SkillMeta { id, name, description(供语义匹配), triggers[], type(TOOL/SUBAGENT), sandbox(bool), enabled }
```

## 4. MCP 高级扩展（§4.3）
- **注册发现**：用户"授权连接"平台 MCP；高级用户自建 MCP Server 配置存 `.mcp/`。
- **连接管理**：WSS/stdio 连接池 + 健康探活（心跳超时重连）。
- **Tool 适配**：MCP Tool → LangChain4j Tool 适配层。
- **Tool Search 按需加载**：系统提示词只注入 MCP Server 目录，具体工具 schema 在模型决定调用时再加载，避免初始 token 爆炸。
- **授权隔离**：每 MCP 独立授权范围，调用经权限安全校验（§4.12 越界防护）。
- **配置**：连接配置存本机 `.config/`，不依赖服务端数据库。

## 5. 多模型路由增强（§4.14 / §6.3）
- 单模型：直通（Phase1）。
- 多模型：路由策略——压缩/匹配用小模型，主推理用大模型；fallback 切备用。
- 路由决策走 `ModelRouter`，配置存 `.config/`。

## 6. 多 Agent 并行编排、工具按需召回与透明化
- 工具注册表聚合 Skill + MCP + 内置工具；语义匹配 Top-K 注入（§6.3）。
- 多 Agent 并行编排增强：`TaskScheduler` 支持 fan-out/fan-in，子代理并行度受 `core.subagent.maxConcurrency` 与全局模型在途数约束，结果由 `ResultAggregator` 汇总回主 Agent。
- 外部 Hook：在已锁定的 Hook 事件上增加 Shell/Webhook/MCP Tool 适配器，支持用户自定义策略与审计；deny-wins 语义不变。
- worktree 隔离：副作用密集的子代理运行在独立 JGit worktree，完成自动清理。
- 前端面板展示：本次调用 token 数、模型调用次数、缓存命中率、各工具触发次数、复杂任务小任务列表与进度、子代理执行进度。

## 7. 技术需求方案与思路架构分析

> 本章对 Phase 3 扩展能力类技术需求展开方案与架构权衡。

### 7.1 Skill 管理（§4.2 / §6.3）
**需求**：Skill 注册/语义匹配/热插拔；省 token 不全量注入；安全边界。
**方案与思路**：
- **注册与映射**：平台预装随包 `.platform/`，用户安装到 `.skills/`；每个 Skill 映射为 LangChain4j 的 Tool/子 Agent，经 `agent-core` 的 `ToolGateway` 注册。
- **语义 Top-K 召回**：`SemanticMatcher` 对用户意图向量化，与 Skill `description/triggers` 向量比对，召回 Top-K（默认 5）注入——**核心降本点**：只注入相关 Skill，避免全量 Tool 塞爆上下文（§6.3）。向量能力复用 `agent-memory` 本地索引，不引云端。
- **热插拔**：`SkillLoader` 运行时加载/卸载，不重启内核——满足用户"装完即用"。
- **安全边界**：Skill 脚本执行仍经本机执行臂 `realpath` 越界防护（§4.11）；执行沙箱默认关，开启需用户授权——与文件操作共用同一硬边界，不另造防护。

### 7.2 MCP 扩展（§4.3）
**需求**：外部工具接入，授权即用，连接可靠。
**方案与思路**：
- **注册发现**：用户"授权连接"平台 MCP；高级用户自建 MCP Server 配置存 `.mcp/`；连接配置存 `.config/`（零托管）。
- **连接管理**：WSS/stdio 连接池 + 健康探活（心跳超时重连）——保障 MCP 这种外部长连接不稳定场景下的可用性。
- **Tool 适配**：`ToolAdapter` 把 MCP Tool 映射为 `agent-core` 统一的 `Tool`，调用经权限安全校验（§4.12）。
- **授权隔离**：每 MCP 独立授权范围，未授权不注入其 Tool——把"授权"做在注册边界而非执行时，简化运行时。

### 7.3 多模型路由增强（§4.14 / §6.3）
**需求**：多模型时分层降本；单模型仍直通。
**方案与思路**：
- 单模型：退化为直通（与 Phase1 一致）。
- 多模型：`ModelRouter` 路由策略——压缩/匹配用小模型，主推理用大模型；fallback 切备用。决策配置存 `.config/`。
- **架构边界**：路由是 `agent-model` 内部策略，对 `agent-core` 透明（core 只拿 `ChatResponse`）；分层模型仅是"多模型进阶用户"增强，非 ToC 默认（呼应 §6 修正）。

### 7.4 工具按需召回与透明化
**需求**：聚合 Skill+MCP+内置工具；前端可见成本。
**方案与思路**：
- 工具注册表聚合三类 Tool，语义 Top-K 注入（§6.3 落地）。
- 前端透明面板：token 数 / 模型调用次数 / 缓存命中率 / 各工具触发次数——把"框架帮用户省钱"显性化，提升信任。
- 计数统一在 `agent-common` 埋点，避免各模块散落统计。

### 8.2 本轮偏差与修复说明

1. **真实 token 数据断流修复**：`ReactEngine` 原 `tokenUsed` 硬编码为 0，透明面板无数据；本轮接入 `MetricsCollector.reportModelCall` 与真实 `tokenMeter.count(messages)`，发布真实 `AgentEvent.token`。
2. **事件流订阅聚合**：`MetricsCollector` 订阅 `AgentEventPublisher.stream(sessionId)`，按 `token/action/tool_result/skill_invoke/mcp_invoke/task_progress` 聚合；工具调用次数与成败统一在 `tool_result` 裁决，避免 ACTION 重复计数。
3. **缓存命中率**：取自 `FingerprintCache` 全局真实计数器（hits/misses），诚实反映本机缓存收益；非严格按会话隔离。
4. **契约约束**：遵循契约定义禁止 Web/CLI 扩展事件类型，透明面板采用 REST 轮询 `/api/chat/{sessionId}/metrics` 而非新增事件。
5. **构建依赖修复**：`agent-core` 缺失 `agent-cache` 依赖（`MetricsCollector` 引用 `FingerprintCache`），已补 `pom.xml`；`MetricsCollector` switch 用字符串常量（`event.type()` 返回 JSON 字符串而非枚举）；`SessionMetrics.snapshot()` 因 `Map.of` 上限 10 键改用 `LinkedHashMap`。
6. **CLI 历史编译错误**：`package.log`/`cli-compile.log` 中 `CliRunner` 缺 `import java.util.Map` 为历史快照，当前源码已含该导入，本轮全量编译通过。
