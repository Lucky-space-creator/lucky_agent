# Phase 4 实现文档：Workflow + RAG + CLI

> 关联需求：待办「工作流模块 p4、RAG 模块 p4」；Roadmap Phase 4；八项差距 D20 AgentChannel。
> 目标：基于 LangGraph4j 实现 DAG 工作流，基于 LangChain4j RAG 编排（核心）+ Spring AI VectorStore/EmbeddingModel（辅助）实现检索增强，并交付随本地部署包提供的 CLI 通道。

## 1. 阶段目标
- 工作流：LangGraph4j `StateGraph` 支持 LLM 节点、工具节点、条件节点、代码节点，串行/并行/条件分支，DAG 编译期校验与运行期调度。
- RAG：LangChain4j ContentRetriever（核心）+ Spring AI VectorStore/EmbeddingModel（辅助），向量库抽象、数据源管道、分块/嵌入、混合召回、评估闭环。
- CLI：随本地部署包一并交付，通过 `AgentChannel` + `Flux<AgentEvent>` 复用内核，不新增业务逻辑。

## 2. 涉及模块与交付物
| 模块 | 交付内容 |
|---|---|
| agent-workflow | LangGraph4j DAG 组件目录、编译器、调度器、上下文作用域、沙箱执行 |
| agent-rag | 向量库抽象、数据源管道、分块/嵌入、混合召回、评估闭环 |
| agent-cli | CLI 入口（Picocli、REPL、非交互批量）、AgentChannel 适配、终端渲染 |
| （复用） | agent-core / agent-memory / agent-workspace / agent-permission / agent-executor / agent-model / agent-skill / agent-mcp / agent-cache / agent-common / agent-prompt |

## 3. 工作流模块（agent-workflow）
- 组件：LLM 节点 / 工具节点 / 条件节点 / 代码节点；组合组件支持子流程、循环、分支。
- 编排：`StateGraph` 定义 DAG，编译期校验权限、变量作用域、死锁；运行期按边条件驱动。
- 执行：每个节点经执行臂校验，失败按策略重试/跳过/终止。
- 沙箱：代码/工具节点默认进沙箱，资源与文件系统边界受控。

## 4. RAG 模块（agent-rag）
- 形式：Naive RAG / ReAct RAG / Agentic RAG / Graph RAG，按场景选择。
- 向量库：多引擎抽象接口，集合按知识库分库，元数据与向量分离。
- 召回：默认稠密 + BM25 混合召回（RRF 融合），重排序后取 Top-K。
- 数据源：本地文件 / 网页 / 数据库 / API，管道为抓取→清洗→分块→嵌入，支持增量同步。
- 评估：离线召回率/NDCG，在线反馈，评估→调参→再评估闭环。

## 5. CLI 架构
- CLI 进程内嵌内核，通过 `AgentChannel` 消费同一 `Flux<AgentEvent>`；协议以 `resources/file/契约定义.md` 为准。
- 命令示例：`lucky init / chat / workspace add / model config / memory clear / skill list|enable|disable / workflow run <dag> / rag index <source> / rollback <checkpointId>`。
- 工作流和 RAG 均可通过 CLI 触发，事件流与 Web 一致。

## 6. 验收点
- [ ] LangGraph4j DAG 可编译、可执行，串行/并行/条件分支正确。
- [ ] 工作流节点执行受执行臂校验，失败按策略降级。
- [ ] RAG 混合召回可用，向量库引擎可替换，评估指标可输出。
- [ ] CLI 初始化工作空间、运行 chat/workflow/rag 与 Web 端行为一致。
- [ ] CLI 与 Web 消费同一 `AgentEvent` 事件流，进度展示一致。
- [ ] 工作流/RAG 数据均在本机，无云端存储。
