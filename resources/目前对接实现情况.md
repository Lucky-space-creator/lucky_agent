# P2 / P3 前后端对接现状

> 调研时间：2026-08-26。结论：Phase2/Phase3 实现文档中标注"验收通过"的部分能力，实际只做到了后端 Service 层，没有暴露 REST Controller，前端因此无法接入，与验收文档描述有出入。

## 1. 后端有接口，前端已对接（正常）

- 对话、工作区、文件、模型端点 CRUD、权限规则、账号信息：Controller + `api/index.ts` 封装 + Vue 界面均齐全。
- 透明面板指标：`MetricsController` → `/api/chat/{sessionId}/metrics`，前端 `TransparencyPanel.vue` 已渲染 tokenUsed / modelCalls / cacheHitRate / windowUsage / lastModel / toolCounts / skillInvokes / mcpInvokes / subAgents。

## 2. 后端有接口，前端没接（可直接补前端）

- **清除我的记忆**：后端 `PrivacyController` 已提供 `POST /api/privacy/clear-memory`，前端 `accountApi.clearMemory` 也已封装，但没有任何界面按钮调用它，用户点不到。
- **透明面板字段不全**：`SessionMetrics` 里的 `cacheHits`、`cacheMisses`（命中/未命中明细）、`contextWindow`（上下文窗口原始上限值）没有在面板上展示，只显示了算好的 `cacheHitRate` 和 `windowUsage` 百分比。

## 3. 后端只有 Service，没有 Controller（前端接不了，需先补后端）

以下能力在 Phase2/Phase3 文档中被列为"验收通过"，但只存在内部 Service/类，没有 REST 层，前端无法调用：

- 执行回退/一键撤销：`RollbackService`、`CheckpointSnapshoter`、`SnapshotIndex`（agent-executor）
- 模型 Key 轮换/重填/密钥链切换：代码里实际没做，`ModelController` 只有 list/save/delete/probe
- Prompt Cache 命中/写入明细：`PromptCacheService`（agent-model），只在 metrics 里聚合成 cacheHitRate，没有独立可查接口
- 缓存模块状态查询：`agent-cache` 模块无 Controller
- 多模型路由策略：`ModelRouterImpl` 存在，无 Controller
- 多 Agent fan-out/fan-in 管理：`TaskScheduler`（agent-core）存在，无 Controller，前端只能通过 metrics 里的 subAgents 字段间接看进度
- 外部 Hook 管理：`LifecycleHookDispatcher`（agent-core）存在，无 Controller

## 4. 确认完全不存在的模块

- `agent-skill`、`agent-mcp` 模块整个不存在，无 Skill 注册/MCP 连接相关代码。
- JGit worktree 隔离相关代码不存在。

这两项在 Phase3 验收文档里本就标注为"➖ 未在本轮实现"，与本次调研结果一致，不是前端遗漏。

## 5. 处理方式

本轮先只处理第 2 类（前端能直接接的）：
1. 在设置/隐私相关界面加"清除我的记忆"按钮，接入已有的 `accountApi.clearMemory`。
2. `TransparencyPanel.vue` 补全 `cacheHits`/`cacheMisses`/`contextWindow` 三个字段的展示。

第 3、4 类涉及新增后端 Controller 或功能本身未实现，不在本轮前端界面开发范围内。

## 6.只有后端 Service、没有 Controller，前端根本无接口可调的（做前端界面前得先补后端 REST 层）：

- 执行回退/检查点撤销（RollbackService/CheckpointSnapshoter 存在，无 Controller）
- 模型 Key 轮换/重填/密钥链切换（代码里根本没实现，ModelController 只有 list/save/delete/probe）
- Prompt Cache 明细观测（只在 metrics 里聚合了命中率，没有独立接口）
- 缓存状态查询（agent-cache 模块无 Controller）
- ModelRouter 策略配置（ModelRouterImpl 存在，无 Controller）
- TaskScheduler fan-out/fan-in 管理（TaskScheduler 存在，无 Controller，前端只能通过 metrics 的 subAgents 间接看进度）
  - 外部 Hook 管理（LifecycleHookDispatcher 存在，无 Controller）
