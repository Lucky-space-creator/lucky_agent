# agent-cache 模块实现文档

> 对应需求文档：§4.6 缓存模块、§6 缓存治理

## 一、模块定位

`agent-cache` 负责工程缓存（非用户记忆）：会话消息缓存（仅 3 天）、工具结果缓存（带指纹）、上下文压缩缓冲、击穿保护。全部在用户本机内存，不引入云端 Redis。

**责任边界**：
- 缓存读/写/过期清理/降级。
- 不负责记忆持久化（那是 memory 模块）。

---

## 二、实现框架（分层）

```
agent-cache
├── api/
│   ├── SessionCache.java       # 会话消息缓存契约
│   ├── ToolResultCache.java    # 工具结果缓存契约
│   └── dto/ CacheKey, CacheVal
├── session/
│   ├── SessionMessageCache.java  # 仅最近 3 天
│   └── TtlSweeper.java           # 3 天 TTL 定时清理
├── toolresult/
│   ├── FingerprintCache.java      # 上下文指纹缓存
│   └── Fingerprinter.java        # 文件hash + 记忆版本
├── buffer/
│   └── CompressBuffer.java        # 上下文压缩缓冲
├── protect/
│   └── CachePenetrationGuard.java # 击穿保护 + 降级
└── config/ CacheConfig.java
```

**目录落盘（§3.0）**：`.cache/` 会话消息缓存（3 天 TTL）+ 工具结果热缓存（可重建，3 天过期）。

## 三、实现思路（核心设计）

### 3.1 会话消息缓存（仅 3 天，§4.6）

- 缓存仅保存用户**最近 3 天的对话消息与会话上下文**，按用户/工作区隔离（本地 Caffeine）。
- 超过 3 天的消息/会话由 `TtlSweeper` 本地定时清理，避免无限堆积占内存/磁盘。
- 落盘 `.cache/` 仅为加速冷启动，重启可重建；超 3 天自动清除。

### 3.2 工具结果缓存（带指纹，R5）

- `FingerprintCache` 以"上下文指纹"（文件 hash + 会话标识 + 记忆版本）为 key，避免陈旧命中。
- 同参数不重跑；指纹变化即失效重算。

### 3.3 上下文压缩缓冲（90% 阈值触发）

- `CompressBuffer` 配合 §4.13 上下文压缩：**当上下文占用率到达 90% 阈值（`model.context.threshold`，默认 0.9）时**，先把待压缩的旧窗口片段缓冲进来，再交由压缩器执行滑动窗口/摘要/下沉，避免一次性截断关键信息。
- 缓冲压力随"占用率 − 阈值"增大而收紧：超出越多，缓冲越激进（更多过程类内容进入待压缩），保证在占用率逼近 100% 前完成回落。
- 异常降级：压缩失败时跳过缓冲直接转 ASK（不静默丢上下文），由 model 兜底流程接管。

### 3.4 击穿保护与降级

- `CachePenetrationGuard`：空值/异常时本地降级（跳过缓存直接调用），无需 Sentinel。
- 缓存异常不影响主链路。

## 四、关键配置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| cache.session.ttlDays | 3 | 会话缓存 TTL |
| cache.tool.ttlDays | 3 | 工具结果缓存 TTL |
| cache.backend | Caffeine | 本机内存 |
| cache.sweepCron | 0 0 3 * * ? | 每日清理 |

## 六、具体设计

> 核心思路：cache 是加速层，不是必需层。用 common 缓存守卫（Caffeine）实现，3 天 TTL 用定时清理；工具结果带指纹。异常一律降级。不过度设计分布式缓存。本模块只做职责、流程与边界层面的设计，不涉及具体代码实现。

### 6.1 核心职责
- **会话缓存**：按 `userId+workspaceId+sessionId` 隔离，3 天 TTL；最近消息可快速回放，重启后可从落盘重建。
- **工具结果缓存**：以"参数 + 文件 hash + 会话标识 + 记忆版本"生成指纹，指纹变则未命中重算，避免陈旧结果（R5）。
- **指纹生成器**：统一产出上述指纹串。
- **TTL 清理**：定时（每 6h）或读取时判定过期，超 3 天清除。
- **降级守卫**：缓存异常时跳过缓存直接走计算，主链路不崩。

> 落盘的 `.cache/` 属框架隐藏目录，对用户不可见；用户工作区不受影响。

### 6.2 设计模式应用
- **策略模式**：缓存守卫多实现（Caffeine/Redis 桩），业务无感。
- **模板方法**：降级守卫固定"尝试命中→否则计算→异常降级"骨架。
- **装饰器**：工具结果缓存在缓存守卫上叠加指纹逻辑。

### 6.3 验收点（具体）

- [ ] 写入消息后超 3 天，判定过期返回空。
- [ ] 改文件内容使文件 hash 变，旧工具结果未命中，重算。
- [ ] 缓存异常时降级守卫仍返回计算结果，主链路不崩。
- [ ] 不同 `userId` 的会话缓存 key 不同，互不可见（隔离验证）。
- [ ] 落盘 `.cache/` 文件超 3 天被清理任务删除。
