# agent-executor 模块实现文档

> 对应需求文档：§4.11 本机执行臂、§4.9 文件操作、§4.7 执行回退

## 一、模块定位

`agent-executor` 是框架的**执行侧**，包含本机执行臂（必备桥接客户端）、本机文件操作、执行回退。它是访问用户本机文件的唯一可行路径（R1）。

**责任边界**：
- 本机执行臂：守护进程、`ExecutionTransport` 信道（Phase 1 本机 IPC，方案 B 时 WSS）、本端越界防护、文件/命令执行、防劫持。
- 文件操作：仅在工作空间内读写/解析（无 MinIO，产物只落本机）。
- 执行回退：本机快照（按 workspaceId 分桶），一键撤销。
- 权限规则定义归 permission，但执行臂本地持有规则副本并重新评估 `deny > ask > allow`；框架侧裁决仅作提示，执行臂守住 `realpath` 硬边界。

## 二、实现框架（分层）

```
agent-executor
├── api/
│   ├── ExecutorClient.java     # 执行臂调用契约（框架服务端侧）
│   ├── FileService.java        # 文件读写契约（限工作空间）
│   ├── RollbackService.java    # 回退契约
│   └── dto/ FileOp, ExecResult, Snapshot
├── arm/                         # 本机执行臂（随客户端安装）
│   ├── ArmDaemon.java          # 启动器/守护进程（开机自启/重连）
│   ├── ExecutionTransport.java # 传输抽象（Local/IPC；远端 WSS 可切换）
│   ├── LocalTransport.java     # Phase 1 本机进程内/IPC
│   ├── PermissionRuleCache.java # 执行臂本地权限规则副本
│   ├── BoundaryGuard.java      # realpath 越界防护（硬边界）
│   ├── FileExecutor.java       # 读/写/删/执行（限工作空间）
│   ├── CmdSandbox.java         # 命令执行沙箱（默认关闭）
│   └── IntegrityChecker.java   # 进程完整性/防劫持校验
├── fileops/
│   ├── LocalFileService.java   # 文件读写/类型分发
│   └── TypeDispatcher.java     # 类型分发解析（触发 Skill）
├── rollback/
│   ├── CheckpointSnapshoter.java  # 检查点快照
│   ├── SnapshotIndex.java         # 快照索引（按 workspaceId 分桶）
│   └── Compensator.java           # 补偿重放
└── config/ ExecutorConfig.java
```

**目录落盘（§3.0）**：
- 用户产物：`<workspaceRoot>/<workspace>/`。
- 回退快照：`<frameworkRoot>/.rollback/`（按 workspaceId 分桶）。
- 执行臂程序与运行态：`<frameworkRoot>/.agent/`。
- 锁文件/临时中转：`<frameworkRoot>/.tmp/`（锁契约见下）。

## 三、实现思路（核心设计）

### 3.1 本机执行臂（§4.11，必备组件）

- **部署**：随框架安装到用户机器（桌面客户端/后台服务），开机自启、常驻、断线重连。
- **通信与鉴权**：Phase 1 经 `ExecutionTransport` 本机 IPC（进程内/本地通道），不引入 WSS；方案 B 时切换 WSS 加密长连接 + 双向鉴权，业务模块不感知传输差异。
- **本端越界防护（硬边界，最终裁决者）**：`BoundaryGuard` 在**执行臂本地**对每次文件/命令做 `realpath` 规范化，阻断 `../`、符号链接逃逸出工作空间——**无论 LLM/框架服务端如何决策，执行臂是唯一最终裁决者**，不越界（R2）。MVP 以 realpath 为硬边界，Phase 2 补 symlink 双路径检查、复合命令拆分与 OS 级沙箱。
- **防劫持**：`IntegrityChecker` 进程签名校验，被替换则拒绝启动；命令执行 (`CmdSandbox`) 默认关闭，开启需用户显式授权。
- **Web 文件链路**：前端 → 框架文件服务 → 指令下发给执行臂 → 执行臂本机授权目录执行 → 结果回传（框架服务端不接触文件内容）。

### 3.2 文件操作（§4.9）

- 框架**不存储**用户文件/图片（无 MinIO）；产物只写本机工作空间目录。
- `LocalFileService` 仅在工作空间内读写/解析；解析结果触发 Skill，内容交 `agent-memory` 注入短期记忆（文件模块自身不做记忆注入）。
- 全程受权限沙箱约束。
- **磁盘满等本机 IO 异常**：捕获 IO 异常，提示"工作空间所在磁盘已满，无法执行文件操作"，由用户清理后重试（用户侧事项，不做配额/清理）。

### 3.3 执行回退（§4.7）

- 关键操作前在**本机**生成快照（文件版本/状态点，按 `workspaceId` 分桶存 `.rollback/`）。
- 回退即还原本机快照，不依赖消息队列。
- 用户感知为"一键撤销"，粒度=检查点（每次关键操作一个检查点，可逐步回退）。
- 用户**主动删除**文件夹的恢复与提示策略见 **第六节、七**（回收站软删除 + 误删恢复入口）。

### 3.4 `.tmp/` 锁文件契约（R10，防死锁）

- **命名**：`<workspaceId>.<relPath>.lock`，首行写 **PID + 获取时间戳 + 租约超时（默认 30s）**；原子写（先 `.lock.tmp` 再 `rename`）。
- **获取**：已存在则读首行——PID 不存在（进程已死）或超时 → 视为 stale 锁，直接抢占覆盖；否则等待重试（带总上限，防无限阻塞）。
- **释放**：`try-finally` 删锁；正常退出由 JVM `ShutdownHook` 兜底清理本进程持有的锁。
- **启动清理**：进程启动扫描 `.tmp/`，删除 PID 已不存在或超时的 stale 锁；`.part` 中转文件一并清理。

## 六、具体设计

> 核心思路：executor 是唯一"碰用户本机文件"的组件。设计两半——**框架服务端侧转发指令** 与 **本机侧真正执行 + 硬边界**。执行臂为权限与越界的最终裁决者，框架服务端仅转发指令与元数据、不接触文件内容。锁契约用 `agent-common` 的锁守卫实现。不过度设计，不引入 MQ。本模块只做职责、流程与边界层面的设计，不涉及具体代码实现。

### 6.1 核心职责

框架服务端侧（framework 进程内）：
- **执行臂客户端**：经 `ExecutionTransport`（Phase 1 本机 IPC；方案 B 时 WSS）把文件操作指令下发给本机执行臂，仅传指令/元数据，不碰文件内容。

本机侧（arm 进程内，随客户端安装）：
- **守护进程**：Phase 1 以同进程/本机 IPC 维持连接；方案 B 时与框架服务端建立 WSS 加密长连接并维持心跳。
- **硬边界守卫**：对每次操作先做 realpath 越界校验，越界直接拒绝（保护用户本机）。
- **权限规则执行**：权限规则同步到执行臂本地（`PermissionRuleCache`），执行臂重新评估 `deny > ask > allow`；deny 直接拒绝，ask 转 core 的 ASK；框架侧裁决仅作提示。
- **后续增强**：Phase 2 补 symlink 双路径检查、复合命令拆分（Apache Commons Exec）与 OS 级沙箱。
- **文件执行器**：读/写/删/执行均限制在工作空间内；执行前加文件锁，操作结束释放（try-finally），进程退出由钩子兜底清理。
- **命令沙箱**：命令执行默认关闭，需显式开启。
- **完整性校验**：对执行臂进程做签名校验，防止被替换。

回退（同进程，本机快照）：
- **检查点快照**：关键操作前在 `.rollback/<wid>/` 写快照，记录 `{checkpointId, wid, ts, affectedFiles[], parentId}`，支持逐步回退（一键撤销）。
- **补偿器**：按 checkpointId 还原本机快照，不依赖消息队列。

### 6.2 `.tmp/` 锁契约落地（复用 common 锁守卫）
- `<wid>.<relPath>.lock` 首行 `PID|ts|leaseMs`；原子写 `.lock.tmp`→rename。
- 获取：读首行，PID 死/超时 → 抢占；否则重试带上限。
- 释放：操作结束删锁 + 进程退出钩子兜底。
- 启动：扫描 `.tmp/` 清 stale 锁与 `.part` 中转残留。

> 注意：`.tmp/` 与 `.rollback/` 均属**框架隐藏目录**，对用户不可见；用户自己的工作产物（`<workspace>/` 下）保持可见可操作。

### 6.3 设计模式应用
- **代理模式**：执行臂客户端代理本机执行，框架服务端不碰文件内容。
- **模板方法**：文件执行器固定"越界校验→加锁→doRun→释放"骨架。
- **职责链**：完整性校验 → 本地权限规则重评估 → 硬边界 → 文件执行，逐级把关。
- **命令模式**：文件操作指令可序列化，便于长连接传输与回退记录。

### 6.4 验收点（具体）

- [ ] Phase 1 执行臂走本机进程内/IPC，不依赖 WSS；方案 B 时假证书双向鉴权失败拒绝（模拟中间人）。
- [ ] 硬边界守卫对 `../etc/passwd` 类越界路径抛异常，执行臂不执行。
- [ ] 写操作产物落在 `<workspace>/` 下，抓包验证无上传服务端。
- [ ] 制造 stale 锁（杀进程留锁），新获取抢占成功；启动扫描清理生效。
- [ ] 删文件前快照写入 `.rollback/<wid>/`，还原后一致。
- [ ] 工作空间磁盘满时捕获 IO 异常并转"磁盘已满"提示，进程不崩。
- [ ] deny 规则命中时执行臂拒绝且不执行；symlink 双路径检查在 Phase 2 生效。

## 七、用户主动删除文件夹的恢复与提示策略（场景补充）

> 核心原则：**尊重用户意图，但不让用户"一键误删"无法挽回**。用户在有意识删除（无论是自己在资源管理器删，还是通过对话让 Agent 删）时，框架做"软删除 + 明确提示 + 可恢复窗口"，而非立即物理销毁。

### 7.1 软删除：回收站而非直接销毁
- 无论删除来自"用户手动在文件系统删"还是"Agent 经 ASK 确认的删除"，执行臂在真正 unlink 前先把目标**移入本机回收站**（`<frameworkRoot>/.trash/<wid>/<时间戳>_<原相对路径>/`），保留原始目录结构与元数据（删除时间、操作来源：manual / agent）。
- 物理删除仅在回收站过期清理时发生（默认保留 30 天，可配置），期间随时可恢复。
- 注意：`.trash/` 属框架隐藏目录（位于 `<frameworkRoot>/`），用户工作区其余部分仍可见可操作；回收站对用户透明，不污染其工作区。

### 7.2 提示策略（区分"故意"与"误删"）
- **主动经对话删除**：Agent 执行删除前已走 ASK 确认（危险操作识别命中），删除完成后向用户推送提示："已删除 `xxx/`，可在 30 天内于回收站恢复"——明确告知有反悔窗口。
- **用户在资源管理器手动删除**：框架无法拦截（也无权拦截用户本机操作），但可在下次对话或文件树刷新时做"差异感知"：若被删目录曾受 Agent 管理（在 `.rollback/` 有快照或记忆中记录过），提示"检测到 `xxx/` 已被删除，如需恢复可从回收站/历史快照还原"，**不自动恢复、不替用户做决定**。
- **高危目录保护**：对工作空间根、`.rollback`、`.trash` 等框架目录的删除请求一律拒绝（硬边界），并提示"该目录由框架管理，不可删除"。

### 7.3 恢复入口
- **对话入口**：用户说"恢复刚删的文件夹"/"撤销删除" → 触发回收站还原（按时间/路径匹配最近一条），还原回原相对路径（若原路径已被新内容占用则提示冲突，让用户选覆盖或另存）。
- **一键撤销**：复用 §3.3 的检查点机制——若删除是某次 Agent 操作的一部分，撤销该检查点即还原。
- **回收站浏览**：提供"查看回收站"能力，列出可恢复的删除项与剩余保留期。

### 7.4 设计模式应用
- **命令模式**：删除操作记录为可回收命令（含来源/时间），支持 undo。
- **备忘录/快照**：回收站即轻量快照，与 `.rollback` 检查点互补（回收站管"用户删的"，检查点管"Agent 改的"）。
- **策略**：提示文案按"来源(manual/agent) × 是否受控"分流。

### 7.5 验收点（具体）
- [ ] 对话触发删除后，目标出现在 `<frameworkRoot>/.trash/<wid>/` 且原结构完整，原位置已空；提示含"可 30 天恢复"。
- [ ] 用户在资源管理器手动删掉曾被 Agent 管理的目录，下次刷新文件树时收到"可恢复"提示，但未被自动还原。
- [ ] 对 `.rollback/` 或工作空间根的删除请求被硬边界拒绝并提示"框架目录不可删"。
- [ ] "恢复刚删的文件夹"指令命中最近一条回收站记录并还原至原路径；原路径被占用时提示冲突而非静默覆盖。
- [ ] 回收站超保留期后，后台清理任务物理删除且不影响用户工作区其它文件。
