# Lucky Agent 核心契约定义

> 版本：1.0
> 本文件是 Web / CLI / SDK 共用的协议唯一事实源。契约变更必须通过决策记录，不允许通道各自定义。

## 1. AgentEvent

统一事件结构，所有通道消费同一事件流。

```json
{
  "version": "1.0",
  "type": "thought | content_delta | action | tool_result | skill_invoke | mcp_invoke | task_plan | task_progress | ask | error | token | stop",
  "eventId": "uuid",
  "sessionId": "uuid",
  "taskId": "optional",
  "callId": "optional",
  "ts": "ISO8601",
  "payload": {}
}
```

按 `type` 的 payload 约束：

| type | 关键字段 |
|---|---|
| thought | `content` |
| content_delta | `delta`（最终回复正文流式增量，前端逐字追加） |
| action | `tool`, `args`, `risk` |
| tool_result | `callId`, `source`, `ok`, `summary`, `data?`, `error?` |
| skill_invoke | `skillId`, `match` |
| mcp_invoke | `serverId`, `tool`, `source` |
| task_plan | `tasks: [{ taskId, title }]` |
| task_progress | `taskId`, `status: pending/running/done/failed/ask`, `done`, `total` |
| ask | `question`, `risk` |
| error | `stage`, `callId?`, `msg`, `fallback` |
| token | `used`（本次调用增量）, `input`, `output`, `total`, `model`, `warn?` |
| stop | `reason: success/max_turns/max_budget/error`, `summary?` |

Java 对应 `AgentEvent`，字段名与 JSON 一致，禁止 Web/CLI 各自扩展事件类型。

## 2. HookEvent

固定事件名：`SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / PreCompact / PostCompact / SubagentStart / SubagentStop / Stop`。

输入：

```json
{
  "version": "1.0",
  "hookEventName": "PreToolUse",
  "sessionId": "uuid",
  "cwd": "path",
  "toolName": "optional",
  "toolInput": {},
  "permissionMode": "default | acceptEdits | plan | bypassPermissions",
  "ts": "ISO8601"
}
```

输出：

```json
{
  "version": "1.0",
  "decision": "ALLOW | DENY | ASK | DEFER",
  "decisionReason": "optional",
  "systemMessage": "optional",
  "modifiedInput": {}
}
```

语义：

- 多个 Hook 按注册顺序执行，任一 `DENY` 立即阻断（deny-wins）。
- `systemMessage` 注入对话上下文，用于告诉模型为什么被拦截以及替代路径。
- 内部 Hook 默认不阻塞；外部 Shell/Webhook Hook 后续接入时，沿用同一决策结构。

## 3. PermissionRule

权限规则统一格式，由 `agent-workspace` 或用户配置产生，同步到执行臂本地。

```json
{
  "version": "1.0",
  "id": "rule-id",
  "priority": 100,
  "type": "PATH | COMMAND",
  "matcher": {
    "pattern": "glob or regex",
    "anchor": "//abs | home | project | relative"
  },
  "action": "ALLOW | DENY | ASK",
  "reason": "optional"
}
```

裁决语义：

- 规则按 `priority` 升序执行，`DENY` 永远胜出。
- 无规则命中时按工作区级别走 `ASK` 或 `ALLOW`。
- 路径锚定：`//abs` 文件系统绝对路径、`home` 用户目录、`project` 工作区根、`relative` 当前目录。
- 复合命令先拆分再独立裁决；symlink 双路径检查在 Phase 2 补齐。

## 4. SubAgentSpec

子代理定义格式，Phase 1 定死。

```json
{
  "version": "1.0",
  "id": "subagent-id",
  "name": "code-reviewer",
  "description": "optional",
  "tools": ["Read", "Glob", "Grep"],
  "disallowedTools": ["Write", "Edit"],
  "maxTurns": 20,
  "maxTokens": 50000,
  "permissionMode": "default | acceptEdits | plan | bypassPermissions",
  "summaryOnly": true,
  "isolation": "none | worktree | tmpdir",
  "persona": "optional personaId",
  "skills": []
}
```

约束：

- 子代理只回摘要或结构化结果，不直接回灌完整上下文。
- `disallowedTools` 先减，`tools` 再限定。
- 子代理不提升权限，不绕过 ASK 与执行臂硬边界。

## 5. AgentChannel

通道契约，Web 与 CLI 复用。

```java
public interface AgentChannel {
    Flux<AgentEvent> subscribe(SessionRef session);
    Mono<RunResult> submit(SessionRef session, UserInput input);
    Mono<Void> cancel(SessionRef session);
    Mono<SessionSnapshot> snapshot(SessionRef session);
}
```

约束：

- 通道只负责渲染和输入，不持有业务逻辑。
- 所有状态查询走 `ConversationStateManager`，通道不得自行缓存会话。
- Web 使用 SSE 适配，CLI 使用终端渲染适配，两者消费同一 `Flux<AgentEvent>`。

## 6. ExecutionTransport

执行侧传输契约，本机模式与远端模式共用。

```java
public interface ExecutionTransport {
    Mono<ExecResult> execute(FileOp op, PermissionDecision decision);
    Mono<Boolean> ping();
}
```

约束：

- Phase 1 使用 `LocalTransport`（进程内或本机 IPC），不引入 WSS。
- 方案 B 时新增 `WssTransport`，业务模块不感知传输差异。
- 执行臂本地重新评估权限规则，框架侧决策仅作提示。

## 7. SessionRef

```json
{
  "sessionId": "uuid",
  "userId": "uuid",
  "workspaceId": "uuid"
}
```

所有会话、任务、事件均以 `SessionRef` 定位，禁止使用裸路径或裸 sessionId 跨模块传递。
