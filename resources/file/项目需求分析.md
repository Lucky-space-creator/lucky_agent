# Lucky Agent 项目需求分析与架构设计（Agent 框架版 · 多模块化单体）

> 产品形态：作为 **Agent 服务提供者**，提供类 Claude Code 的智能体框架能力。项目只做 Agent 框架本身，**不托管模型、不收取费用、不做任何用户数据的托管与管理**——用户操作产生的所有数据（记忆/对话/文件产物/配置）一律存放在**用户本机工作空间**，平台不存储、不管理。当前工程为**多模块单机项目**，后续可平滑演进为微服务。 **本地部署优先**：用户下载服务包，通过一键脚本/命令启动，浏览器访问本地 Web 使用；无需云服务器、无需公网 IP。

## 一、项目定位与总体目标

**产品定位**：Agent 框架服务提供者。用户通过 Web 界面，以自然语言驱动 Agent 完成代码编写、文件处理等任务。框架内置长期记忆、可扩展技能与工具调用能力，在用户本机指定路径内安全操作文件。

**边界声明（重要）**：
- 本项目 = **Agent 框架**，不含模型服务、不含计费、不含任何用户数据的服务端托管/管理。
- **不做文件/图片保存（平台侧）**：框架只"操作"用户本机文件，用户数据全在用户工作空间（无 MinIO 用户存储）。
- **不做消息/信息托管**：对话消息、记忆、trace、用户配置等**全部不落任何服务端数据库**，一律驻留用户端电脑内存 / 本机工作空间文件；框架本身不依赖任何数据库或对象存储。
- 模型由外部接入（用户自带 Key 或本地模型），框架只做编排。
- **工程形态**：当前为**多模块 Maven/Gradle 单机工程**（模块化单体），模块间通过清晰接口契约解耦，预留微服务拆分能力。
- **本地部署优先**：用户下载服务包，通过一键启动脚本/命令在本机运行，浏览器访问本地 Web 使用；不依赖云服务器，不要求公网 IP。

**核心设计原则**：
1. **内核与通道解耦**：能力沉淀在后端内核，Web/CLI 仅作交互外壳。
2. **LangChain4j + LangGraph4j 为编排中枢**：LangChain4j 负责 Agent/工具/记忆/RAG，LangGraph4j 负责工作流与多 Agent 图编排（必需）。
3. **多模块分层**：按业务域拆分为独立模块（编排/记忆/权限/文件/缓存…），接口契约清晰，模块可独立测试与替换。
4. **本机优先（零托管）**：用户数据全在用户工作空间；平台不存用户内容，天然隐私合规。
5. **安全优先（保护用户本机）**：Agent 只动用户**显式授权**的路径范围，危险操作必须确认。
6. **单机抗并发**：模块内用线程池/任务队列/本地缓存隔离热点，保护模型调用与下游，预留微服务演进点。
7. **框架中立于模型与计费**：只编排、不收费。
8. **用户指定工作空间**：Agent 操作/存储空间由用户在 Web 端指定本机路径，默认 `C:/lucky_agent`。

## 二、技术框架角色划分（多模块工程 · 本机优先 · 零托管）

> 核心判断：作为 Agent 服务提供者，用户数据全在用户本机工作空间，平台**零托管、零服务端存储**。当前工程为**多模块单机**，用模块化与模块内并发控制抗负载；分布式中间件（SpringCloud/Dubbo/RocketMQ/Redis/Sentinel/MySQL/MinIO）当前**一律不引入**，待真实高并发/多节点需求出现再评估。

| 框架/中间件 | 本项目中的角色 | 必要性 |
|---|---|---|
| Java + Spring Boot | 基础语言与工程骨架（多模块单机 Web 服务） | **必需** |
| 多模块工程（Maven/Gradle） | 按业务域拆分为独立 module，接口契约解耦 | **必需（工程结构）** |
| LangChain4j | Agent 循环、工具调用、记忆、RAG 组件底座（AiServices / ChatLanguageModel / ChatMemory） | **必需（核心）** |
| LangGraph4j | 工作流 DAG、多 Agent 图编排、条件边/子图 | **必需（工作流/多Agent）** |
| Spring AI | 辅助模型/嵌入/向量库/可观测性接入层（Spring Boot 原生集成，不承担 Agent 编排） | **辅助（推荐）** |
| 用户本机资源 | 内存（运行态记忆/对话/缓存/配置）+ 文件系统（工作空间+产物+本机持久化） | **必需（唯一数据主存）** |
| 线程池/任务队列（JDK 原生） | 模块内任务隔离、模型调用在途数控制、异步执行 | **必需（单机抗并发）** |
| MinIO | 用户数据全在本机工作空间，平台不做对象存储 | **不需要** |
| MySQL | 用户配置/产物均存本机文件，框架不依赖任何服务端数据库 | **不需要** |
| Redis | 用户运行态数据在本机内存，云端 Redis 既非必需又违背本机优先 | **不需要（云端）** |
| RocketMQ | 单实例无分布式事件解耦需求；回退/异步靠本机任务队列即可 | **不需要** |
| SpringCloud + Dubbo | 当前多模块单机，无强制跨进程拆分；预留为后续微服务演进方案 | **暂不需要（演进预留）** |
| Sentinel | 单机用本地限流/信号量即可；预留为微服务期流量防护 | **暂不需要（演进预留）** |

> 说明：本项目**只做 Agent 框架**，不引入任何服务端存储（无 MySQL / MinIO / Redis）。用户配置、记忆、对话、缓存、产物**全部在用户本机**——内存 + 文件空间（`<workspaceRoot>/` 产物目录与 `<frameworkRoot>/` 隐藏目录）。框架服务端仅做编排，不持久化任何用户数据。模块化设计使后续可平滑拆为微服务（见第十一章）。

## 二（附）、工程模块划分与单机抗并发设计

> 作为 Agent 服务提供者，工程需具备清晰的多模块边界与抗并发能力，同时维持"零托管"。

### 2.1 多模块工程结构（模块化单体）

按业务域拆分 module，模块间仅依赖**接口契约**（API/DTO），不跨模块直接依赖实现，便于后续整体拆分为微服务。

```
lucky-agent（父工程）
├── agent-core          # LangChain4j/LangGraph4j 编排封装、PLAN-ACT-ASK、子代理/多Agent执行(4.15)
├── agent-memory        # 记忆系统双轨、检索、压缩下沉(第三章/4.13)
├── agent-skill         # Skill 注册/匹配/加载(4.2)
├── agent-mcp           # MCP 注册/适配(4.3)
├── agent-permission    # 权限管理+安全拦截(4.10/4.12)
├── agent-executor      # 本机执行臂客户端(4.11) + 文件操作(4.9) + 执行回退(4.7)
├── agent-persona       # 个性模块(4.1)
├── agent-prompt        # Prompt 模板/静态动态分界/版本管理
├── agent-model         # 大模型配置与路由(4.14)
├── agent-cache         # 缓存/Token治理(4.6/第六章)
├── agent-workflow      # LangGraph4j DAG 工作流编排
├── agent-rag           # RAG 检索/向量库/混合召回
├── agent-workspace     # 工作区管理(4.8)
├── agent-web           # Web 前端接口层（Controller/WebChannel + SSE）
└── agent-common        # 公共契约：DTO/异常/常量/工具
```

**模块契约原则**：
- 每个模块对外暴露 `api` 包（接口 + DTO），实现类不跨模块暴露。
- 跨模块调用走 Spring 依赖注入接口，禁止循环依赖（用事件/回调解耦）。
- 预留 `@Remote` 标记：未来需拆微服务时，被标记接口即为 RPC 边界。

### 2.2 单机抗高并发设计（不引入分布式中间件）

单实例需扛住多用户并发对话与模型调用，措施全部基于 JDK/Spring 原生能力：

| 并发热点 | 本地手段 | 说明 |
|---|---|---|
| 模型调用在途数 | 信号量/有界线程池 | 限制同时打向模型的请求数，防线程耗尽（R6） |
| 对话任务排队 | 单用户串行队列 + 全局公平池 | 同一用户对话串行，避免交错；全局池防单用户占满 |
| 记忆/文件读取 | 本机读写锁 + 文件版本号 | 防并发写用户工作空间冲突 |
| 缓存命中 | 本地 Caffeine 缓存（按用户/工作区隔离） | 语义/工具结果缓存，零网络开销 |
| 长任务不阻塞 | Project Reactor `Flux<AgentEvent>` + SSE 推送 | 前端流式感知，内核线程不被长推理占死 |
| 限流降级 | 本地令牌桶（Guava RateLimiter） | 单实例入口与模型端点限流，预留 Sentinel 替换点 |

**演进预留**：上述本地手段均在 `agent-common` 中封装为统一抽象（如 `ConcurrencyGuard`/`RateLimiter` 接口），未来换 Redis/Sentinel 实现无需改业务代码。

## 三、记忆系统架构（用户层面 / 平台(系统)层面 双轨 · 全在用户本机）

### 3.1 总体分层

```
用户原始输入 / Agent 产出（运行时在本机内存，落盘在本机文件）
      ↓
[噪声过滤层]   规则 + 轻量判别，过滤无意义、重复、超限
      ↓
[数据清洗层]   结构化抽取（意图/实体/结果），脱敏
      ↓
[分层记忆层]  ← 按归属拆分【用户层面】与【平台(系统)层面】
      ↓
[事实萃取层]   置信度评估 + 冲突检测 + 去重聚合
      ↓
[沉淀事实层]   高置信事实进本地知识库（本机向量/文件）
```

横切：**检索层** 与 **遗忘/衰减机制** 同时作用于两层面，全部在本机内存 + 本机文件完成。

### 3.0 工作空间目录结构规范（统一约定，必选）

用户数据分为两部分：
- `frameworkRoot`：框架隐藏目录唯一根，默认 `%LOCALAPPDATA%/lucky_agent` 或 `${user.home}/.lucky_agent`，承载配置、记忆、缓存、日志、回退、回收站等框架数据。
- `workspaceRoot`：用户指定路径（默认 `C:/lucky_agent`，或用户指定 `D:/mycode`），只放用户产物。

框架所有模块必须严格按此落盘，禁止在工作空间之外写入用户数据：

| 目录 | 用途 | 由谁写入 | 是否落盘 |
|---|---|---|---|
| `<workspaceRoot>/<workspace>/` | 各工作区用户产物（代码/文档/生成文件），按 `workspaceId` 隔离 | 4.9 文件操作模块 | **必选落盘** |
| `<frameworkRoot>/.config/` | 用户配置 / 工作空间权限级别（只读·修改·全部）/ 工作空间映射 / 模型 Key 与端点 URL（加密）/ MCP 连接配置 / 人格配置 | 4.10 权限、4.14 模型、4.2/4.3 接入、5.1 账号 | **必选落盘** |
| `<frameworkRoot>/.memory/` | 用户层面记忆持久化（JSONL + 本地向量索引） | 3.2 记忆模块 | **必选落盘** |
| `<frameworkRoot>/.platform/` | 平台预置记忆（随框架包内置，用户只读） | 发行包 / 框架升级 | **必选落盘（只读）** |
| `<frameworkRoot>/.rollback/` | 关键操作检查点快照（文件版本/状态点，按 `workspaceId` 分桶），支持一键撤销 | 4.7 执行回退 | **必选落盘** |
| `<frameworkRoot>/.cache/` | 会话消息缓存（仅最近 3 天）/ 工具结果缓存（Caffeine 溢出/进程重启后的本地热缓存，格式结构化文件，按 3 天 TTL 过期） | 4.6 缓存模块 | **可选落盘**（运行态在内存，重启后可重建；落盘仅为加速冷启动，超 3 天自动清除） |
| `<frameworkRoot>/.logs/` | 操作审计日志（仅元数据，不含文件内容）、模型调用 trace、运行诊断 | 4.10/4.12 审计、模型调用层 | **必选落盘（仅元数据）** |
| `<frameworkRoot>/.skills/` | 用户自定义/安装的 Skill 脚本与配置（平台预置 Skill 随包在 `.platform/`） | 4.2 Skill 模块 | **必选落盘** |
| `<frameworkRoot>/.mcp/` | 用户自建 MCP Server 配置与脚本（平台 MCP 配置在 `.config/`） | 4.3 MCP 模块 | **必选落盘** |
| `<frameworkRoot>/.tmp/` | 并发读写锁文件、文件版本号标记、临时中转文件（**锁文件命名契约见下**，进程退出/启动可清理） | 2.2 并发控制、4.9 文件操作 | **临时落盘** |
| `<frameworkRoot>/.trash/` | 回收站软删除（按 `workspaceId` 分桶，默认保留 30 天） | 4.7 执行回退/4.11 执行臂 | **必选落盘** |

> **`.tmp/` 锁文件契约（防残留死锁 · 必选）**：
> - **命名**：锁文件格式 `<workspaceId>.<relPath>.lock`，文件首行写入持有者 **PID + 获取时间戳 + 租约超时（默认 30s）**；读写为原子写（先写 `.lock.tmp` 再 `rename`）。
> - **获取**：尝试建锁，若已存在则读首行——PID 不存在（进程已死）或 超时已过 → 视为 stale 锁，直接抢占并覆盖；否则等待并重试（带总上限，避免无限阻塞）。
> - **释放**：操作结束 `try-finally` 删锁；正常退出由 JVM 钩子（`Runtime.addShutdownHook`）兜底清理本进程持有的锁。
> - **启动清理**：进程启动时扫描 `.tmp/`，删除 PID 已不存在或超时过期的 stale 锁（§2.2 读写锁统一配超时）。
> - **临时中转文件**：`<workspaceId>.*.tmp.part`，落盘即标记、用完即删；启动期一并清理残留 `.part`。
| `<frameworkRoot>/.agent/` | 本机执行臂（4.11）自身程序与运行态（守护进程、连接态、本地权限缓存与规则副本） | 4.11 执行臂 | **必选落盘（客户端侧）** |

> 约定：以 `.` 开头为框架隐藏目录（配置/记忆/缓存/日志/元数），无前缀为用户可见产物。除 `.tmp/` 外，所有目录删除需用户显式确认（受 4.12 权限拦截）。新增任何"需要落盘的模块数据"必须在此表中补列目录，禁止私自在工作空间外写盘。

**本机存储分工（必选，非可选）**：
- **运行时态**：记忆/对话/缓存驻留**用户端电脑内存**，保证低延迟。
- **跨会话持久化（必选）**：定期/事件触发落盘到 `<frameworkRoot>/.memory/`，格式为结构化文件（JSONL + 本地向量索引）。进程退出/重启后自动加载恢复，否则长期记忆形同虚设。
- **不落云端**：上述数据从不发往任何远端存储，仅在本机内存/本机文件。

### 3.2 用户层面记忆（User-level Memory）
- **归属**：绑定单用户，跨项目可用，体现个人偏好与历史。
- **内容**：语言/语气偏好、常用技术栈、私人决策与踩坑、个人沉淀知识。
- **存储**：**用户端电脑内存**（运行时）+ **必选本机文件持久化**（跨会话恢复）；**不落云端**。
- **ToC 要点**：默认开启、用户无感；提供"清除我的记忆"（清本机文件 + 内存）。
- **隔离**：仅本机用户，天然隔离。

### 3.3 平台(系统)层面记忆（Platform-level Memory）
- **归属**：平台级公共知识，随框架/版本**预置或随包更新**到用户本机，不参与实时网络下发。
- **内容**：通用编程常识、平台使用约定、公共 Skill/MCP 经验、全局安全规范。
- **存储**：随框架发行包内置到**用户本机**（`<frameworkRoot>/.platform/`），运行时加载进本机内存参与推理；不含个人隐私。
- **ToC 要点**：用户只读；更新随框架升级，不实时回传用户数据。

### 3.4 双轨协同规则

| 维度 | 用户层面 | 平台(系统)层面 |
|---|---|---|
| 归属 | 本机用户 | 框架预置→本机加载 |
| 优先级 | 个性化覆盖建议 | 规范性兜底 |
| 冲突 | 用户偏好优先（除非 FORCE 约束） | `FORCE` 安全/合规不可覆盖 |
| 写入 | 用户交互累积（仅落本机文件） | 框架发行包 |

> 隐私防火墙（机制而非声明）：用户层面记忆**只写入本机文件，无任何上行通道**；平台记忆更新走"框架升级包"而非"用户数据回传"，从架构上物理隔断用户记忆上漂平台的可能（见 R6）。

### 3.5 与 LangChain4j/LangGraph4j 结合
- 记忆作为 Memory Module/Tool，全部在本机内存 + 本机文件；短期记忆绑 Conversation/session；长期与沉淀事实作外部 Provider 注入（Provider 后端即本机文件索引）。
- 注入时按用户+平台两层面分别召回并打标；启动时从本机 `.memory/` 与 `.platform/` 加载。

## 四、功能模块架构（逐模块）

### 4.1 智能体个性模块
**模块列表**：个性配置中心、行为参数引擎、多 Agent 角色编排器（执行委托 core）、个性-Skill 绑定器
**实现架构**：
- 默认预设人格（如"严谨工程师""快速助手"），零配置可选；进阶自定义 System Prompt 与行为参数。
- 个性配置存**本机 `.config/`**（用户文件空间内），运行时注入 LangChain4j/LangGraph4j。
- 多 Agent 协作由 `agent-core` 子代理执行器统一调度，persona 只提供角色与人格，对用户透明。

### 4.2 Skill 管理模块
**模块列表**：Skill 注册中心、语义匹配器、依赖解析器、热插拔加载器、执行沙箱
**实现架构**：平台预装常用 Skill，用户开关；每个 Skill 映射为 LangChain4j 的 Tool/子 Agent，支持热插拔；运行时语义匹配 Top-K 注入（非全量，省 token）。

### 4.3 MCP 扩展服务模块
**模块列表**：MCP Server 注册发现、连接管理器、Tool 适配层、用户授权隔离器、健康探活
**实现架构**：MCP 多为平台能力，用户点"授权连接"；自有 MCP 供进阶；调用经权限安全校验。MCP 连接配置存**本机 `.config/`**。

### 4.4 PLAN-ACT-ASK 三层执行模式（底层即 REACT）
**模块列表**：PLAN 计划生成器、ACT 执行调度器、ASK 询问挂起器、计划置信度评估器、重规划器
**实现架构（本次修订：底层统一 REACT）**：
- **PLAN / ACT / ASK 不是独立的嵌套循环，而是 REACT 推理范式在不同阶段的封装**：
  - **PLAN 阶段** = REACT 以"产出可执行计划"为目标的若干步（Thought→规划 Action→Observation 校验）。
  - **ACT 阶段** = REACT 以"执行单步"为目标的循环（Thought→工具 Action→Observation），每步复用同一 REACT 引擎。
  - **ASK 阶段** = REACT 在"信息不足/需决策"时，Action 变为"向用户提问"并挂起，用户输入后作为 Observation 续跑。
- 三者共享一个 REACT 引擎（4.5），仅系统提示/目标/终止条件不同，避免双层循环失控（由统一 REACT 引擎 + 步数上限约束保证）。
- 计划对象需有 schema 契约 + 计划校验器，非法计划强制重规划（见 4.5）。

### 4.5 REACT 框架（统一底层引擎）
**模块列表**：推理循环引擎、工具调用网关、观察结果归一化器、计划校验/解析器
**实现架构**：
- 单 REACT 引擎服务于 PLAN/ACT/ASK 三阶段（4.4）。每轮 Thought/Action/Observation 进本机记忆与追溯。
- **步数上限 + 早停**：单阶段超步数强制转 ASK/重规划，防无限试错（降本）。
- **计划校验器**：PLAN 输出经格式契约校验，非法则拒绝并重规划（补原缺口）。

### 4.6 缓存模块（工程缓存，非用户记忆）
**模块列表**：会话消息缓存、工具结果缓存、上下文压缩缓冲、击穿保护器
**实现架构**：
- 缓存存**用户端电脑内存**（按用户/工作区隔离），不引入云端 Redis。
- **近期消息缓存（仅保留最近 3 天）**：缓存仅保存用户**最近 3 天的对话消息与会话上下文**，超过 3 天的消息/会话由本地定时清理任务自动清除（落盘部分见 §3.0 `.cache/` 同样按 3 天 TTL 过期），避免无限堆积占内存/磁盘。
- 工具结果缓存带"上下文指纹"（文件 hash + 会话标识），避免陈旧命中（见 R7）。
- 缓存异常时本地降级（跳过缓存直接调用），无需 Sentinel。

### 4.7 执行回退模块
**模块列表**：检查点快照器、快照索引管理器、补偿重放器、回退触发器
**实现架构**：
- 关键操作前在**用户本机工作空间**生成快照（文件版本/状态点，按 `workspaceId` 分桶存本机 `.rollback/` 目录）；回退即还原本机快照，不依赖任何消息队列。
- ToC 用户感知为"一键撤销"，撤销粒度=检查点（每次关键操作一个检查点，用户可逐步回退到指定检查点）。

### 4.8 工作区管理模块
**模块列表**：工作区命名空间管理器、工作区配置中心、任务分解进度器
**实现架构**：
- 轻量化——工作区即"一个工作区/一个需求会话"，建名即用；资源按 `workspaceId` 在本机工作空间内隔离。
- **权限级别（用户配置）**：用户添加工作空间时选择该工作区的操作权限级别——**只读 / 修改文件 / 全部权限**（含执行）；权限级别随工作空间配置存于本机 `.config/`。每次对话调用时将该工作区的权限级别带入上下文，精确权限由 `deny > ask > allow` 规则链裁决，LLM 判断仅作体验引导。
- **工作空间配置归属**：工作空间路径映射（`workspaceId ↔ 物理路径`）与权限级别存本机 `.config/`，不依赖任何服务端数据库（遵守本机优先零托管）。

### 4.9 文件操作模块（框架只操作，不保存）
**模块列表**：文件读写服务（本机工作空间内）、类型分发解析器、Skill 触发器
**实现架构**：
- 框架**不存储用户文件/图片**（无 MinIO）；Agent 生成的产物**只写入用户本机工作空间目录**（如 `<workspaceRoot>/<workspace>/`），不向任何服务端上传。
- 仅在本机工作空间内读写、解析；解析结果触发 Skill（如代码审查、摘要），解析出的内容交由 `agent-memory` 模块（§3.5）注入短期记忆，文件操作模块自身不做记忆注入。
- 全程受权限沙箱约束。
- **磁盘满等本机 IO 异常**：写文件失败（如工作空间所在磁盘已满）属用户本机环境异常，框架不替用户做配额/清理，仅捕获 IO 异常并提示"工作空间所在磁盘已满，无法执行文件操作"，由用户自行清理后重试。

### 4.10 Agent 权限管理模块（工作空间配置中心）
**模块列表**：
- 工作空间注册器（用户指定本机路径 ↔ 逻辑工作区）
- 工作空间代理服务（访问用户本机文件的桥梁，含本机执行臂）
- 工作空间权限级别配置（只读 / 修改文件 / 全部权限，用户选择）
- Web 文件操作服务（前端入口与转发层；实际读写经本机执行臂 4.11 在用户本机完成，框架服务端只转发指令与元数据，不落用户文件内容；权限规则链裁决，执行臂为最终执行边界）
- 权限审计日志

**实现架构（重点，本次修订：用户指定路径 + 默认 workspaceRoot）**：
- **用户指定路径**：用户在 Web 端"添加工作空间"，填写本机一个目录（如 `D:/mycode`）作为 Agent 操作与存储空间；平台生成 `workspaceId` 绑定 `userId` 与该路径。
- **默认路径**：未指定时，默认在 `C:/lucky_agent`（workspaceRoot）下创建文件夹与子文件夹（如 `<workspaceRoot>/<workspace>/...`），Agent 在此建子目录组织产物。
- **权限级别由用户配置（非细粒度矩阵）**：用户添加工作区时选择操作权限级别——**只读 / 修改文件 / 全部权限（含执行）**，配置随工作空间存于 `<frameworkRoot>/.config/`。每次对话调用时，框架将该工作区的权限级别作为上下文带入对话；精确权限由 `deny > ask > allow` 规则链裁决，**执行臂是物理执行边界与越界的最终裁决者**（见 4.11）。
- **Web 操作本机文件**：浏览器不直连文件系统。前端请求 → 后端文件服务 → **本机桥接/代理**（用户机器上的执行臂）在授权目录内执行 → 返回结果。代理 `realpath` 校验防 `../` 穿越。
- **本机执行臂安全**：桥接程序内置 `realpath` 越界校验（防逃逸工作空间），执行臂硬边界为唯一生效源，防框架服务端指令被绕过。详见 4.11 本机执行臂独立架构。
- **高危操作提示**：删除/执行/覆盖等高风险动作，框架在对话中向用户确认（ASK），由用户最终拍板，而非框架侧硬编码拦截矩阵。
- **与 4.11 关系**：本模块管"工作空间与权限级别配置"，4.11 管"本机执行与越界防护"，权限级别数据存本机 `.config/`、随调用带入上下文。

### 4.11 本机执行臂（桥接客户端）【独立一等公民组件】

> 定位：执行臂是访问用户本机文件的唯一执行侧。Phase 1 为纯本机单体，内核与执行臂同进程或本机 IPC；演进到方案 B（云端服务端 + 本机执行臂）时，再启用 WSS 加密长连接。执行臂本地重新评估权限规则，是权限与越界的最终裁决者。

**模块列表**：
- 启动器/守护进程（开机自启、常驻、断线重连）
- 双向信道（`ExecutionTransport`：Phase 1 本机 IPC；方案 B 时 WSS 长连接 + 心跳）
- 本端越界防护器（realpath 防逃逸工作空间）
- 文件操作执行器（读/写/删/执行，限工作空间内）
- 命令执行沙箱（执行权限受控，默认关闭）
- 防劫持校验（进程完整性校验；远端模式增加信道双向鉴权）

**实现架构**：
- **部署形态**：Phase 1 为纯本机单体，执行臂与内核同进程或本机 IPC；用户安装框架时一并安装本机执行臂。Web 端"添加工作空间"时，执行臂上报本机目录可用性；工作空间路径映射（逻辑 `workspaceId↔物理路径`）与权限级别配置**存本机 `<frameworkRoot>/.config/`**，不依赖任何服务端数据库。
- **通信与鉴权**：`ExecutionTransport` 抽象统一本机与远端模式；Phase 1 使用本机 IPC，方案 B 时切换 WSS 加密长连接 + 双向鉴权，业务模块不感知传输差异。
- **本端越界防护（硬边界，最终裁决者）**：所有文件/命令操作在**执行臂本地**先做 `realpath` 规范化，阻断 `../`、符号链接逃逸出工作空间；执行臂本地重新评估 `deny > ask > allow` 权限规则（规则同步到本地），框架侧裁决结果仅作提示，以执行臂本地校验为唯一生效源。
- **防劫持**：执行臂进程做完整性校验（签名校验），本机恶意软件替换执行臂会导致校验失败拒绝启动；命令执行默认关闭，开启需用户显式授权。
- **Web 文件操作链路**：前端 → 框架文件服务 → 下发指令给执行臂 → 执行臂在本机授权目录执行 → 结果回传前端。框架服务端**不接触用户文件内容**，只转发指令与元数据。

### 4.12 权限安全模块（越界防护 + 危险操作确认）
**模块列表**：路径越界校验器、工具调用拦截器、危险操作确认器、操作审计与可撤销
**实现架构**：
- **权限级别由对话驱动**：用户为每个工作区配置的权限级别（只读/修改/全部）随调用带入上下文；精确权限由 `deny > ask > allow` 规则链裁决，**执行臂为权限与越界的最终裁决者**（见 §4.10/§4.11）。
- **本机越界防护（防逃逸）**：**本机执行臂（4.11）**对每次文件/命令操作做 `realpath` 规范化，阻断 `../`、符号链接逃逸出工作空间——这是框架必须守住的硬边界（无论 LLM 如何决策，执行臂不越界）。
- 危险操作（删除/执行/覆盖）框架在对话中 ASK 向用户确认，结合 4.7 快照撤销。
- 审计仅记操作元数据，不留存文件内容（隐私）。

### 4.13 上下文压缩模块
**模块列表**：Token 计量器、滑动窗口策略、摘要压缩器、层级压缩(下沉本机长期记忆)、关键信息保全器
**实现架构**：监控 Token（本机内存），**上下文占用率到达 90% 阈值（`model.context.threshold`，默认 0.9）自动触发**滑动窗口/摘要/下沉；占用率 = 会话已用 token ÷ 模型上下文窗口；保全计划/安全约束/关键结果；用户无感。

### 4.14 大模型配置模块（纯接入，不收费）
**模块列表**：模型端点接入中心、模型路由策略、参数配置中心、API Key 加密管理、fallback 与健康探测
**实现架构**：
- 配置"端点 URL + Key"（用户自带或本地模型）；路由策略（多模型时分层，单模型时退化为直通）；Key 与端点 URL **加密存本机 `.config/`**（框架不依赖服务端数据库）；fallback 切备用。
- **本地配置直连（不引入平台唯一 ID / 不做激活配对）**：用户在本地配置模型端点与 Key，框架仅**读取本机 `.config/` 中的配置去调用 LLM**，全程不向平台上报 Key/URL、不引入平台专属 ID、不做 token 校验与激活配对。用户本地存 Key 与 URL 即可，框架职责是**保障其不被泄露**（见下方加密）。
- **Key 加密（防泄露手段，非独立风险项）**：模型 Key 与端点 URL 均用**用户口令派生（PBKDF2）或 OS 密钥链**加密存 `.config/`，禁止随包硬编码（否则加密形同虚设）；口令丢失走"重填 Key"应急。只要保障本机落盘加密、内存不外泄，即满足"Key 不泄露"要求，无需额外平台侧 ID/token 机制。
- **泄露防护边界**：框架自身不存储、不回传用户 Key；第三方模型训练/调用风险由用户 Key 责任方承担（明示），框架仅确保本机落盘加密、内存中不外泄。

### 4.15 子代理与多 Agent 任务执行模块

**模块列表**：子代理工厂与注册中心、任务分解器、执行调度器（串行/并行）、结果聚合器、上下文隔离与继承器、权限安全继承器、任务追溯器、任务进度器

**实现架构**：
- **默认单 Agent**：常规对话由主 Agent 走 PLAN-ACT-ASK 完成；仅当任务可分解且子代理执行收益明确时启用多 Agent 编排。
- **子代理创建**：主 Agent 经 `agent-core` 的 `SubAgentFactory` 创建子代理，子代理可复用 `agent-persona` 的角色/人格配置与 `agent-skill` 的能力集。
- **任务分解与调度**：`TaskDecomposer` 将主任务拆为独立子任务，`TaskScheduler` 支持串行、并行、fan-out/fan-in 三种编排模式；并行度受 `agent-common` 线程池与信号量约束，不突破全局模型在途数上限。
- **复杂任务拆分与进度展示**：主 Agent 判定任务复杂时，将主任务拆成小任务列表；每项小任务有独立 `taskId` 与状态（待执行/执行中/已完成/失败/挂起），进度经 SSE 推送到对话界面，Web/CLI 展示任务列表、当前步骤与完成比例。
- **上下文隔离与继承**：每个子代理绑定独立 `taskId`/`sessionId`，中间结果隔离；继承主 Agent 的工作区、权限级别与安全约束。
- **结果聚合**：子代理完成后由 `ResultAggregator` 汇总，返回主 Agent 继续决策；前端/CLI 默认展示统一结果，可按需展开子任务进度。
- **安全边界不变**：子代理不提升权限、不绕过 ASK，所有文件/命令操作仍走本机执行臂的 `realpath` 硬边界与权限级别强制。
- **失败与降级**：子任务失败/超时按策略重试、降级为单 Agent 或转 ASK，不静默失败。
- **可追溯**：子代理每轮 Thought/Action/Observation 写入本机记忆与 `.logs/` trace，用户可查看执行链路。

### 4.19 AI 框架集成边界（LangChain4j + LangGraph4j 核心 · Spring AI 辅助）

**职责划分**：
- **LangChain4j**：Agent 循环、工具调用、ChatMemory、RAG 编排抽象（AiServices / ToolProvider / ContentRetriever）。
- **LangGraph4j**：工作流 DAG、多 Agent 图编排、条件边与子图（StateGraph）。
- **Spring AI（辅助层）**：模型端点接入、EmbeddingModel、VectorStore、可观测性（ChatModel / EmbeddingModel / VectorStore / Observation），不承担 Agent 编排。

**桥接方式**：
- `SpringAiModelAdapter`：实现 LangChain4j `ChatLanguageModel`，内部委托 Spring AI `ChatModel`。
- `SpringAiVectorAdapter`：实现 LangChain4j `EmbeddingStore`/`ContentRetriever`，内部委托 Spring AI `VectorStore` 与 `EmbeddingModel`。
- LangGraph4j 节点可调用 LangChain4j Agent/工具，工作流与 Agent 循环不重复实现。

**约束**：编排统一走 LangChain4j/LangGraph4j；Spring AI 不直接承担 Agent 循环，只承担模型与向量层，避免三套编排抽象。

## 五、ToC 支撑模块（不含计费）

### 5.1 账号与用户体系（本机本地，无中心化用户库）
- 框架不依赖服务端用户库；账号为**本机本地身份**（存本机 `.config/`），用于隔离多用户本机配置与记忆。
- 本机身份仅用于本机多用户配置/记忆隔离；LLM 调用采用**本地配置直连**（用户自带 Key+URL，框架只读本机配置调用），不引入平台唯一 ID、不做激活配对（详见 §4.14）。
- 登录/会话在本机完成；个人中心：工作空间与权限管理、模型接入配置、记忆清除（清本机）。

### 5.2 隐私与合规
- 数据最小化：用户文件/消息/记忆**不出本机内存**（框架不存）。
- "清除我的记忆"清本机；明确"平台不存储用户内容"，第三方模型训练风险由用户 Key 责任方承担（明示）。

## 六、Token 治理策略（横切）

> 框架帮用户把模型调用成本压最低。目标：少输入、少调用、少试错。

### 6.1 根因
上下文堆积、工具全量注入、重复调用、无效探索。

### 6.2 三层治理
- **输入侧**：Skill/工具按需召回 Top-K、上下文压缩、Prompt 精简。
- **处理侧**：分层模型（压缩/匹配用小模型）、REACT 步数上限+早停、批处理、预检索。
- **输出侧**：语义缓存（带上下文指纹）、工具结果缓存、低置信早停 ASK。

### 6.3 关键措施
| 措施 | 归属 | 机制 |
|---|---|---|
| 工具按需召回 | 4.2 | 语义匹配 Top-K |
| 上下文压缩 | 4.13 | 滑动窗口/摘要/下沉 |
| 分层模型 | 4.14 | **多模型时**小模型做辅助；单模型 ToC 下退化为"Prompt 精简 + 压缩 + 缓存"为主 |
| REACT 步数上限 | 4.5 | 超步数转 ASK/重规划 |
| 语义缓存(指纹) | 4.6 | 文件hash+记忆版本 |
| 工具结果缓存 | 4.6 | 同参数不重跑 |

> **ToC 单模型前提修正**：多数 ToC 用户仅自带单一 Key/单模型，无法路由到轻量模型。此时降本主手段应为 **上下文压缩（4.13）+ 语义/工具缓存（4.6）+ Prompt 精简（4.1）+ REACT 步数上限（4.5）**，分层模型仅作为"多模型进阶用户"的增强项，不应作为默认预期。

### 6.4 实施要点
- 压缩优先用本地小模型（若用户配了）；缓存按用户/工作区隔离；前端展示 token/调用数（透明化）。

## 九、架构风险评估（基于前述设计推导）

> 评估口径：仅依据本文档已明确的真实设计（§2–§8、§3.0、§4.8、§4.11 等）推导风险，不引入文档未定义的中间件/假设。已缓解项标注落地位置，未覆盖项标注"待细化/新增"。

### 9.1 已识别风险清单（仅限框架自身责任）

> 职责边界：本项目 = **Agent 智能体框架服务提供者**。风险评估**只覆盖框架自身缺陷**——尤其是"因框架实现问题导致用户隐私泄露"这一核心红线。用户侧问题（用户主动引入的外部项目内容、用户本机磁盘/文件损坏、网络断线、用户误操作等）**不计入框架 bug/缺陷**，仅在对应模块以"错误处理/提示"形式体现，不在此表内。

| 编号 | 风险（框架责任） | 等级 | 现状/缓解（依据文档章节） |
|---|---|---|---|
| R1 | 部署拓扑：Web 操本机文件必须本机桥接 | 高 | **已落地**：§4.11 本机执行臂独立设计为必备组件 |
| R2 | 本机执行臂被劫持绕过沙箱（致越权/泄露） | 高 | **已缓解**：§4.11 本端 `realpath` + 本地权限规则重评估、进程完整性签名校验；远端模式增加 WSS 双向鉴权；§4.12 框架服务端+本机双层拦截 |
| R3 | PLAN 无契约致非法计划执行 | 中 | **已缓解**：§4.5 计划校验器 + schema 契约，非法强制重规划 |

### 9.2 风险趋势小结

- **已闭环（高→缓解）**：R1/R2/R4/R7 由本机执行臂、双轨物理隔断、必选本机持久化落地。
- **框架责任已明确（非用户侧）**：R10（锁残留防死锁）机制已在 §3.0 `.tmp/` 锁文件契约落地（PID+超时+stale 抢占+启动清理）；模型 Key/URL 的泄露防护已由 §4.14 本机加密存储（PBKDF2/OS 密钥链）覆盖，不另列风险。
- **已剔除的用户侧事项（不计入框架缺陷）**：外部项目 Skill/规则风险、本机目录治理/磁盘占满、本机文件损坏、执行臂断线、ASK 断线状态丢失——均属用户本机环境或用户主动行为，框架仅做"提示/降级/不崩"的错误处理（见 §4.9/§4.11），不作为 bug 跟踪。

## 十、分阶段落地建议（Roadmap · 多模块单机）

**Phase 1（MVP 基础框架闭环 · 架构锁定）**：锁定底层技术栈（JDK 17+ / Spring Boot 3.x / Maven / LangChain4j + LangGraph4j（核心）+ Spring AI（辅助））；交付本地部署包与一键启动脚本（`lucky start` / `start.bat` / `start.sh`）；Spring AI 辅助模型/嵌入/向量库接入层；通过 `ExecutionTransport` 本机模式（进程内/IPC）连接执行臂；实现 `ConversationStateManager` + `Flux<AgentEvent>` 控制流与 WebChannel；落地 `resources/file/契约定义.md`；定义内部 Hook 事件契约；落地 `deny > ask > allow` 基础权限规则链与执行臂本地重新裁决；实现子代理基础执行（任务分解、串行子代理、摘要返回、独立预算、结果聚合）；复杂任务拆分与对话界面任务列表/进度展示；Tool 契约含 `ToolAnnotations`（只读并行/写串行/错误即数据）；`CompactionPipeline` 接口与工具结果裁剪/基础摘要；提示词静态/动态分界；记忆双轨、模型本地配置直连（Key 加密落盘）、Web 文件操作、目录规范与 `.tmp/` 锁契约。
**Phase 2（安全与成本优化）**：权限增强（symlink 双路径、复合命令拆分、OS 沙箱、电路断路器）；提示词缓存与子代理 `inherit`（按模型供应商能力接入 `cache_control`）；五级压缩流水线补齐（Microcompact/Snip/Reactive Compact、preservedSegment、PreCompact/PostCompact 归档、失败熔断）；Token 计量（jtokkit）、熔断（Resilience4j）；执行回退、隐私合规、模型 Key 管理增强、前端 token/调用透明化。
**Phase 3（扩展能力）**：Skill/MCP 高级增强（版本管理/隔离加载/Tool Search 按需加载）、外部 Hook（Shell/Webhook/MCP Tool）、多模型路由增强、多 Agent 并行编排增强（fan-out/fan-in、JGit worktree 隔离）、前端任务与调用透明面板。
**Phase 4（Workflow + RAG + CLI）**：基于 LangGraph4j 实现 DAG 工作流，基于 LangChain4j RAG（核心）+ Spring AI VectorStore/EmbeddingModel（辅助）实现检索增强，并基于 `AgentChannel` + `Flux<AgentEvent>` 交付 CLI（Picocli），复用同一内核、配置、记忆与执行臂。
**Phase 5（微服务演进，按需）**：当单机并发达瓶颈，按 2.1 的 `@Remote` 边界将热点模块（core/memory/model）拆为独立服务，引入 SpringCloud/Dubbo + Redis/Sentinel；Redis 只放元数据或索引，不放用户消息（见第十一章）。

## 十一、微服务演进预案（预留，非当前实现）

> 当前不做微服务；本章仅为后续平滑演进定义边界与触发条件，避免后期重写。

**触发条件**：单实例 CPU/内存/模型在途数持续打满、或需独立扩缩容某模块（如记忆检索）时。

**拆分边界**：以 2.1 的 module 为粒度，被 `@Remote` 标记的接口即 RPC 边界；拆分时：
- 引入 **SpringCloud + Dubbo** 做服务治理与 RPC；
- 引入 **Redis** 承接跨节点缓存/会话（替代本机 Caffeine，仍不存用户内容）；
- 引入 **Sentinel** 做服务间限流熔断；
- 引入 **RocketMQ** 仅当出现跨服务异步事件（如回退事件链）需求；
- MySQL/MinIO **仍不引入**（用户数据始终在本机工作空间）。

**原则**：演进只改部署拓扑与 `agent-common` 中并发/缓存抽象的实现，不动业务模块代码。
